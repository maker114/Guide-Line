## v2.7.4 — 到点提醒（本地通知），Windows 版首次随版本发出

> 2026-10-06：原先这里写的是 `v2.7.0`，但 2.7.0 ~ 2.7.3 **从没发出去过** ——
> 与其补四个 Release，不如一次发当前版本，正文里把这几版讲的事一起带上。

这一篇跨了好几个小版本，你真正能感觉到的变化有四处：

1. **新增：到点了会告诉你**（下面那一节）
2. **改了：「逾期」看时刻** —— 写了具体钟点的任务**到点就算逾期**，不必等到第二天；
   只写到哪一天的仍旧按天（明天才算逾期）。逾期横幅、角标、「已逾期」组与行内标红
   共用同一个判据
3. **修了：到期日的显示** —— 今天到期的也完整显示 `2026-10-06 16:30（今天）`；
   **真的放不下才退成短句**（原先留多少位置是估的，导致"还剩半行空着"的行也被截）；
   另修掉一处省略号从中间切断日期的排版毛病（`2026-10-05（昨…`）
4. **电脑端首次随版本发出** —— 同一个 Release 里也有 `guideline-windows-2.7.4.zip`

### 新增：到点提醒

这一版加的是**提醒**：只有你在任务上写了具体钟点（`10-03 18:00`），它才会在到期之前提醒你。

**怎么开**：「更多 → 提醒」把总开关打开（默认是关的）。

怎么提醒：

- 一条任务**两档**：默认**提前 1 小时**与**提前 10 分钟**。数值可以改，每档也可以单独关掉。
- **到点那一刻不提醒** —— 只在到期之前说一声。
- **只提醒写了钟点的任务**。只写到哪一天的不提醒：给"某天要做"编一个具体钟点，
  是编出来的信息。
- 新建任务时，如果"提前 1 小时"那档已经过去了，会**立刻补一条**
  「还有 25 分钟到期」—— 说的是真实剩余时间，不是那一档原本的提前量。
- **点通知直接落到那条任务所在的事件**；打开应用时的横幅与角标仍然保留。

⚠️ **小米 / HyperOS 上有一件事必须你来做**：给 GuideLine 打开「自启动」
（系统设置 → 应用设置 → 应用管理 → GuideLine → 自启动）。

不开的话：**手机重启后提醒会静默消失**，不报错也不提示。这是系统在拦，
不是本应用能绕过去的 —— 实测日志里那句 `process is not permitted to auto start`
就是这么来的。原委与实测记录写在「更多 → 提醒」页里。

**电脑端不做提醒**，但这一版起 **Windows 版跟着一起发**：同一个 Release 里既有
`guideline-2.7.0.apk`，也有 `guideline-windows-2.7.0.zip`（解压后双击 `guideline.exe`，
不写注册表、不需要安装；数据在 `%LOCALAPPDATA%\GuideLine`；与手机各存各的，
要搬数据走「导出 / 导入」）。

验收：`flutter analyze --no-pub` 0 问题；`flutter test --no-pub` 989 例全绿；
真机（小米 15 Pro / HyperOS / Android 16）实测通知到点，偏差 1~4 秒。

## v2.2.0 — 让"假的成功"无处藏身：一批会悄悄丢数据的毛病

这一版没有新界面。修的是**几处会悄悄弄丢数据、或者骗你说"改好了"的毛病**，
外加一处"拆不动"的结构死结。

主题可以用一句话概括：**凡是"操作报成功、盘上却没写"的路径，这版全部收口了** ——
它们比一个当场报错的 bug 危险得多，因为你下次启动才会发现东西没了。

### 会丢数据的（三处）

- **被"更新版本"锁住时不再假装成功**。你的数据文件如果被**新版** App 写过，
  旧版就看不懂它；旧版的做法是**什么都不写**——但它**照样弹"保存成功"**。
  你改了一整晚，退出后发现全没了。
  更狠的是「从备份恢复」：它连**内存里**的数据都换成了恢复的那份，界面看着一切正常，
  而磁盘上一个字节没动。
  现在这种情况会明确告诉你「主数据文件由更新版本的 App 写入，本次改动没有保存，
  请升级 App」，并把改动退回去。
- **「版本高于本应用」不再靠看中文提示判断**。原来它匹配提示语里有没有"高于"两个字
  —— 改一句文案就失灵，旧版会拿一份**空数据**盖掉你的新数据。现在改成看**数据类型**。
- **日期口径收成一把尺子**。同一个日期（例如 `2026-02-31`，2 月没有 31 号）
  在三处"逾期"判定里会算出**三个不同结论**：横幅与角标说它不逾期，全部任务页却把它
  标红。现在日期在**存进文件时就检查"这一天真实存在吗"**，写入侧和读取侧同一把关。

### 备份：以为保住了，其实没有（三处）

- 「至少保留一份备份」原来数的是"备份列表里有几条"，把**读不出来的坏文件**也算进去了
  —— 数字看着够，实际一份能用的都没有。
- 手动备份判断成功的方法，问的是"盘上有没有这个文件"，而不是"**这一次**写成了没有"。
- 每天的快照是**直接复制**的。写到一半断电会留下半截文件，而程序看到文件存在就以为
  "今天已经存过了"，于是**当天再也不存**，还把一份好的旧快照挤掉。

### 界面上的自相矛盾

- 「全部任务」按紧迫度分组时，同一个任务会**既被说成"未计入逾期"、又被标红**。
- 「删除项目」确认框里那句"30 天后自动清除"原来**写死了 30**，与回收站真正的保留期
  是两处巧合相等 —— 哪天改了期限，这句承诺会照旧说 30 天，你按它算日子，东西早没了。

### 结构：解开"拆不动"的那处死结

`event_detail_page` 里几个小组件原来不是靠传参数，而是**直接伸手去读父页面的私有数据**
—— 像零件焊死在机身上，想单独拆下来修是不可能的。现在改成正经传参数了。

顺带把两处重复收成一份：「删除事件」确认框（文字逐字相同、但**数任务数量的算法不一样**，
一改就会分叉）、四处多选里的「全选」判断。

### 顺手清掉的

- 几处**没人用**的死代码（`dataRevision`、`canonicalTextOf`、两个零调用的计数器等）
- 几处**与代码矛盾**的注释（它们比没有注释更坏 —— 会把人带偏）
- `.tmp` 垃圾清理原来漏了 `exports/` 子目录；判据也从"列清单"改成"扫目录"，
  以后新增写盘点不必记得回来登记

### 验收

`flutter analyze` 0 问题；`flutter test` **881 例全绿**。

**这一版的重点不在于"改了多少"，而在于"每一处都有突变测试"** ——
也就是把修复**改回旧写法**，确认用例真的会红。做了十几处，其中揪出过我自己
引入的回归（日期"年份补零"漏了、手滑放宽了空格），都已修正。

### 已知的、这一版**没做**的

- 一批整洁度欠账（`_Bullet` 三份、`_Field` 两份、测试里的造数据函数 22 份约 991 行）
  —— 它们不影响功能，其中 `_Field` 那两份**不是同一个控件**，合并等于重做
- 全部 881 个测试都跑在开发机上，**没有做过真机验证**

## v1.9.3 — 两条用例不再依赖 Windows 专用命令，CI 首次变绿

CI 从建立起就一直红：两条用例用了 Windows 专用命令，Ubuntu runner 上直接抛异常。

`1.9.2` 推上去之后 GitHub 立刻来报：CI #6 失败。查下来**不是这两天的改动** —— 从 2026-09-27
加这个 workflow 的那次提交起（run #1…run #7），`analyze + test` 这个作业**一次都没绿过**，
`build apk (release)` 则一直成功。病因是本机（Windows）与 CI（Ubuntu）的差异：
两条用例用 Windows 专用命令 `attrib` 制造写盘失败。

- **CI 从建立起就一直红**：`test/core/atomic_file_test.dart` 与
  `test/app/app_controller_test.dart` 原先靠 `Process.runSync('attrib', ['+R', …])`
  把文件 / 目录设成只读，而 `attrib` 只有 Windows 有 —— Ubuntu runner 上
  `Process.runSync` 抛 `ProcessException`，连"设不上就 `markTestSkipped`"那句都轮不到。
  现在：前者改成在 `AtomicFile.renameHook` 上**注入**失败（与 `fsyncHook` 同风格，
  两端走同一条确定性路径，顺带把兜底的三条分支都覆盖上）；后者改用跨平台测试助手
  `test/support/readonly_dir.dart`（Windows `attrib` / POSIX `chmod`），设不上就跳过。
  以后再要"制造写盘失败"，只能用这个助手，不许再写平台专用命令。

验收：`flutter analyze` 0 问题；`flutter test` 723 例全绿；
CI run #8（提交 `4c22d5c`）**首次变绿** —— `analyze + test` 与 `build apk (release)` 两个作业都成功。
本版只改测试与 CI 相关代码，应用行为没有变化。

本版另附一次仓库维护：**补打 16 个缺失的版本标签**（`v1.5.2` … `v1.9.3`）。此前从 `v1.5.1` 之后一直没打过标签，标签与 Release 是两回事，这次只补了标签。
（口径更正：**只补了标签**，没有为 `v1.6.0`~`v1.9.3` 建 Release —— 已发布的 Release 仍是开头列的五个。）
