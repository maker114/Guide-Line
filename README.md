# GuideLine

**本地优先的个人生活管理工具** —— 把「灵感」和「任务线」两条线管清楚。
当前形态是 **Android 单机版**，用 Flutter 写，数据全部留在你自己的手机上。

## 它是什么

一个**只用自己手机**的生活管理工具。两个核心对象：

- **灵感** —— 速记优先：随手扔进输入框，之后再决定分配、合并进项目、或者丢掉
- **项目** —— 一件事的容器：目的、实现清单、相关灵感、日期与标识色，最多三层

外加一条**任务线**：每个「事件」是一条线，主线按顺序往下走，每个节点还能挂子任务（就这两层）。

**没有云端、没有账号、没有同步、没有推送。** 数据是手机上的一份 JSON 文件，
可以导出、可以备份。双端方案曾因服务器成本卡住，于是先把单机体验做扎实 ——
来龙去脉见 [`CHANGELOG.md`](CHANGELOG.md) 的 `[1.0.0]` 一节。

## 设计原则

这几条决定了功能长什么样，也是很多"为什么不做"的答案：

| 原则 | 具体表现 |
|---|---|
| **本地优先** | 数据只在手机上。安全靠"原子替换 + 备份轮转 + 导出"，不靠云端 |
| **不做自动联动** | 灵感并入项目 ≠ 任务；清单全勾完 ≠ 项目完成（项目的收尾方式是归档）。唯一出口是你手动点的那一次动作 |
| **输入一律在页面里直接写** | 新建与重命名都是点一下原地编辑，不弹对话框；速记框像系统备忘录，能连着记好几条 |
| **形状走一套 token** | 能点的用胶囊、装东西的用圆角矩形、只有图标的用正圆。改观感只改一个文件 |
| **危险动作不图标化** | 行内只留一个图标入口（设 / 改到期日），删除、归档这类留在动作面板里 —— 图标化会提高误触代价 |
| **数据安全是一等公民** | 没有云端，所以本地备份是唯一的安全网："清空备份"是不可能完成的操作 |
| **宁可先定口径再动手** | 术语与边界写在 [`docs/spec/`](docs/spec/)，代码、界面文案、测试都照它写 |

## 功能

底部四个 Tab。

| Tab | 干什么 |
|---|---|
| **灵感** | 速记、逐条原地编辑、打标签并按标签筛选、长按多选批量分配 / 丢弃 / 删除、多条一起合并进项目 |
| **项目** | 项目树最多三层，每个项目有目的、实现清单、标识色；同时看到这个项目下待处理的灵感 |
| **事件** | 一条事件 = 一条任务线：主线按顺序走，节点下挂子任务；进度、搁置、归档 |
| **更多** | 接下来的任务、全部任务、全局搜索、归档区、主题与背景、备份与恢复、导出 / 导入 |

### 灵感：速记 → 归类 → 合并

- **速记优先**：长按桌面图标 → 速记，一键落到输入框
- **标签就是分类**：写的时候就能打标签，点条目上的标签只看这一类。
  标签只是自己的标记 —— 不影响归属项目、不影响归档与完成判定
- **一键合并**：合并编辑器里的「追加原文」把灵感原文**原封不动**作为新的一行接到项目末尾，
  不自动改写、不润色；只改编辑框，仍要点保存才写盘
- **合并前告诉你哪几条**：多选合并时原文默认展开，看清这次并的是哪几条

### 项目：分类与目标

有下级的算**分类**（只显示名字、色条与汇总），没有下级的算**目标**（全套字段）。
这样"要做什么"和"怎么归类"不会混在同一个视图里。每个项目可以挑一个标识色，
十来种预设 —— 刻意不放开成任意取色，因为标识色的用途是"在树里一眼认出来"，近色反而更难分。

### 项目的「如何解决」：清单 + 正文 + AI 整理

「如何解决」由**两块并存**组成：**清单**是"要做什么"的拆分，**正文**是"整体怎么做"的说明。

- **清单**：可加 / 原地改 / 打勾 / 移动 / 删除，头部显示 `n/m 已完成`。
  三条边界：顺序就是数组顺序、**不参与完成判定**、**与事件里的任务没有任何自动联动**
  （唯一出口是那条一次性动作「建成任务…」）
- **AI 整理成正文**：把清单交给模型，让它写出一段通顺的说明。
  这是本应用**唯一会联网**的功能，边界逐条写死在设置页里 ——
  只发项目名称 / 目的 / 清单条目；灵感原文、事件任务、其它项目一律不发；
  `apiKey` 存在系统安全存储（Android Keystore）里，**不进备份、不进导出**；
  提示词与模型返回的原文都不落盘。生成结果**先给预览**、可编辑，确认后才写入正文
- **导出交接说明**：把项目生成一份 Markdown，含清单、正文、待处理灵感与事件任务线；
  预览可编辑后导出 `.md`，丢给电脑上的 AI 去实现。任务列表用 GitHub 语法
  `- [x]` / `- [ ]`，粘进 issue 也能直接用

### 全部任务：分组与紧迫度

- 分组三选一：**不分组 / 按事件 / 按紧迫度**，与状态筛选叠加使用
- 紧迫度**随日期由绿转红**，共 7 档：逾期→红、今天→橘红、3 天内→橙、5 天内→黄、
  7 天内→黄绿、7 天后→绿、**没排期→灰**；已完成 / 已搁置不再报警，一律走灰
- 到期日一律显示成**「绝对日期 + 剩余天数」**，例如 `2026-09-30（3 天后）` ——
  只给相对天数不知道是几号，只给绝对日期又看不出还剩几天

### 界面与外观

- **7 套主题**：默认蓝 / 墨黑 / 松绿 / 陶土 / 梅紫 / 沙金 / 海松 —— 每套只定一个主色，
  其余交给 Material 3 推导，浅色深色都协调
- **背景图**（实验性）：从相册选图后拷进应用私有目录，可调强度与模糊；
  还能**从图里取一个主色当主题**，按饱和度加权取样，而不是取"出现最多的颜色"——
  照片里最多的往往是灰墙和阴影
- **界面里不硬编码颜色**：所有颜色都从主题取，紧迫度这类语义色阶做成 `ThemeExtension`
- 已完成 / 已搁置的任务**默认折叠下级**，主线与子任务在字号、底色、缩进上明确分层

## 技术

### 分层

```
lib/
  core/       数据层与规则 —— 纯 Dart，禁止 import Flutter
  features/   业务逻辑，Workspace 装全部业务规则
  app/        应用装配与动作门面
  ui/         界面，手机外壳加各 Tab
  platform/   平台适配 —— 唯一允许出现平台判断与插件的地方
docs/         契约、口径、计划与工程说明
test/         契约回归、规则、存储、架构边界、界面与外壳
tool/         一次性脚本（目前只有启动图标生成）
```

分层边界不是靠自觉：`test/core/architecture_test.dart` 扫描源码，`lib/core` 里出现
Flutter import、插件出现在 `lib/platform` 之外，测试就会失败。

### 数据与安全

- **单文件存储** `guideline.json`：临时文件 → flush → rename 的**原子替换**。
  跨实体操作天然全有或全无 —— 比如合并灵感会同时改项目与灵感，不会只成一半
- **界面偏好单独一个** `ui_prefs.json`：折叠状态这类改动频繁，不值得为它重写整份数据
- **备份轮转**：滚动备份最近 **10 份**（`guideline.backup.N.json`），
  每天第一份保存留日快照、最近 **7 天**（`guideline.daily.YYYYMMDD.json`）。
  滚动备份可以**单独删除**，但**至少保留一份**
- **备份的时机**：写数据是"改一下就存住"（防断电、防杀进程）；
  备份只在**一段编辑会话**结束时留一份 —— 否则改得越勤，老备份被挤掉得越快
- **损坏永不静默**：主文件读不出来就隔离现场，并自动从最近备份恢复，
  同时告诉你恢复用了哪一份、隔离文件在哪
- **导出 / 导入**：整份数据导出为 `.json.gz` 经系统分享发出；导入前给摘要与二次确认，
  替换前自动留一份备份，导错了能退回。电脑端旧格式（v1 四文档信封）也能直接导入

### 依赖

Flutter 稳定版（开发时用的是 3.47.5）、Dart SDK `^3.13.4`。运行时依赖只有五个：
`path_provider`、`share_plus`、`file_picker`、`http`、`flutter_secure_storage`。

## 快速开始

只装了 APK 就能用 —— 不登录、不联网、不导入任何东西：**打开就是空的，直接开始记**。

从 [Releases](https://github.com/maker114/Guide-Line/releases) 下载 `guideline-*.apk` 装到手机上。
**升级安装不会丢数据**（同包名同签名，老数据零迁移）。

## 开发

```powershell
flutter analyze --no-pub    # 必须 0 问题
flutter test --no-pub       # 必须全绿（当前 550 例）
flutter build apk --release # 产物 build/app/outputs/flutter-apk/app-release.apk
```

- **跑测试很快**：全量 550 例约 **16 秒**，`analyze` 约 **4 秒**。
  所以"少跑点测试"省不下什么，别往那个方向优化
- **构建时显式给版本号**：`android/local.properties` 会缓存
  `flutter.versionName` / `flutter.versionCode`，不显式指定就会打出一个与界面显示
  不一致的包，而且全程不报错
- **首次构建要留出时间**：Gradle 发行包可能卡在下载上（国内镜像问题）
- **真机上有些事做不到**：HyperOS 不给 `INJECT_EVENTS`、Flutter 语义树也不暴露文字，
  所以点击 / 滑动 / 输入法 / 系统分享面板**必须人工点**。自动能验的只有：
  装得上、启动不崩、版本号对、截图看得到内容

## 不做什么

明确放弃的部分，省得反复讨论：

- **云同步与账号**：服务器成本卡住了双端方案，现阶段只做单机
- **推送提醒**：FCM 在大陆不可用；提醒只在打开应用时发生
- **电脑端**：那份归档工程已于 2026-09-24 从工作区移除，源码可从 git 历史取回
  （归档快照提交 `786b143`），省下约 263 MB
- **桌面小组件**：技术链路已验证跑通，但小米 HyperOS 只收录商店包解析出来的小部件，
  侧载 App 的原生卡片进不了桌面小部件中心 —— 这条路在小米上走不通，不必再试
- **多语言**：暂时只有中文
