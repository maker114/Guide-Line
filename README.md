# GuideLine

本地优先的个人生活管理工具：**把「灵感」和「任务线」两条线管清楚**。
当前形态是 **Android 单机版**（Flutter），数据全部留在你自己的手机上。
当前版本 **1.1.0**（变更记录见 [`CHANGELOG.md`](CHANGELOG.md)）。

> 双端（手机 + 电脑）方案在服务器成本上卡住了，因此先把**单机体验**做扎实：
> 数据全部本地、可导出、可备份，不依赖任何第三方服务。
> 来龙去脉见 `docs/plan/mobile-v1-计划.md`。
> 电脑端（Windows）成果已于 2026-09-24 **从工作区移除**，其完整源码仍可随时从
> git 历史取回：归档快照提交是 `786b143`，取法见下面「目录」一节。

## 功能

底部四个 Tab：

| Tab | 干什么 |
|---|---|
| **灵感** | 速记优先：随手扔进输入框，之后再决定分配 / 合并进项目 / 丢弃；可编辑、可加标签、可长按多选批量处理 |
| **项目** | 项目树（≤ 3 层）+ 目的 / 实现 / 日期 / 三态 / 标识色；灵感合并会写进项目「实现」 |
| **事件** | 每个事件是一条任务线：主线纵向串联、子任务同框、并列任务分叉 / 合流 |
| **更多** | 到期、全部任务、全局搜索、归档区（五个分区可反向找回）、主题与背景、备份与恢复（可删单份）、导出 / 导入 |

另外：**长按桌面图标 → 速记**，一键落到灵感输入框。

### 灵感：速记 → 归类 → 合并

- **逐条可编辑**：动作面板里的「编辑内容」点开就在列表里原地改（不弹对话框）
- **多选批量**：长按任一条进入多选，或点「多选」；可一次分配 / 丢弃 / 删除
- **标签**：给灵感打标签便于分类，标签只是自己的标记，不影响归档与完成判定
- **一键合并**：合并编辑器里的「追加原文」把灵感原文**原封不动**作为新的一行
  接到项目「实现」末尾 —— 不自动改写、不润色；只改编辑框，仍要点保存才写盘
- **两侧都能发起合并**：项目详情页的待处理灵感可以直接点进同一个合并编辑器

### 项目：标识色

每个项目可以设一个标识色（十来种预设，不做任意取色），项目树标题前显示一小段色条。
刻意不放开成任意颜色：标识色的用途是"在树里一眼认出来"，近色反而更难分。
未设置就不显示，老数据不需要迁移。

### 任务线：分叉与合流

并列任务是**和主线并列的支路**，不是主线的附属品：两条支路可以各自往下走，
也可以再**接回同一个后续任务**。做法是给任务加一条独立的「后续边」
（`next_task_ids`），与表达归属的 `parent_task_id` **分开**：

- 分叉点标「分出 n 条支路」，每条支路有带色小标题并缩进一层；
  两条支路重新汇到一处时，那个节点标「n 条支路在此汇合」
- 动作面板里的「接后续任务…」既能挑已有任务，也能**新建一个后续任务**；
  接了第二条后续就是分叉，两条都指向同一个任务就是合流
- 「断开后续…」列出它现在接向谁，断掉一条；合流处断一条就退回单线
- 老数据（只有 `order`、没有后续边）按顺序自动成链，**不需要迁移**；
  数据里出现环时整体退回按顺序解释，界面不会死循环

### 全部任务：分组与紧迫度

- 分组三选一：**不分组 / 按事件 / 按紧迫度**，与状态筛选叠加使用
- 紧迫度**随日期由绿转红**，共 7 档：逾期→红、今天→橘红、3 天内→橙、
  5 天内→黄、7 天内→黄绿、7 天后→绿、**没排期→灰**；
  已完成 / 已搁置不再报警，一律走灰
- 到期日一律显示成**「绝对日期 + 剩余天数」**（`2026-09-30（3 天后）`）——
  只给相对日不知道是几号，只给绝对日期又看不出还剩几天
- 刻意**不做「按项目」分组**：任务在数据上属于**事件**，而事件与项目之间没有关联字段。
  要支持它得先给事件加一个「所属项目」，那是数据契约变更，不在本版范围

### 任务行：能做的直接做，做不了的先说清楚

- 行内直接给出「设 / 改到期日」与「接后续任务…」两个高频图标；
  重命名 / 移动 / 归档 / 删除继续留在「更多」菜单里 —— 危险动作图标化会提高误触代价
- 还有未处理的子任务时，勾选框换成**锁形且不可点**，点它只解释原因。
  原来是"点了才弹错误"，用户得先撞一次墙才知道这一步做不了

### 界面与外观

- **输入一律在页面里直接写**，不弹对话框：项目 / 事件 / 任务的新建与重命名都是点一下原地编辑，
  速记框是一块可以连着记好几条的书写区（像系统备忘录）
- **形状走一套 token**（`lib/ui/theme/shape_tokens.dart`）：能点的用胶囊、
  装东西的用圆角矩形、只有图标的用正圆。改之前圆角是逐处写死的 `circular(12)`，
  想统一观感得翻遍所有控件；现在按用途命名、只改一处
- **7 套主题**：默认蓝 / 墨黑 / 松绿 / 陶土 / 梅紫 / 沙金 / 海松 —— 每套只定一个主色，
  其余交给 Material 3 推导，浅色深色都协调
- **背景图（实验性）**：从相册选图后拷进应用私有目录，可调强度与模糊；
  还能**从图里取一个主色当主题**（按饱和度加权取样，不是取"出现最多的颜色"——
  照片里最多的往往是灰墙和阴影）
- 已完成 / 已搁置的任务**默认折叠下级**，主线任务与子任务在字号、底色、缩进上明确分层
- 界面里**不硬编码颜色**：所有颜色都从主题取，语义色阶（如紧迫度）做成 `ThemeExtension`


## 数据与安全

没有云端，所以数据安全是一等公民：

- **单文件存储** `guideline.json`：临时文件 → flush → rename 的**原子替换**；
  跨实体操作（合并灵感同时改项目与灵感）天然全有或全无
- **备份轮转**：每次保存前留一份滚动备份（最近 10 份），每天第一份保存留日快照（最近 7 天）；
  滚动备份可以在「备份与恢复」里**单独删除**，但**至少保留一份** ——
  没有云端时本地备份是唯一的安全网，"清空备份"应该是不可能完成的操作
- **损坏永不静默**：主文件读不出来就隔离现场，并自动从最近备份恢复
- **导出 / 导入**：整份数据导出为 `.json.gz` 经系统分享发出；导入前给摘要与二次确认，
  替换前自动留一份备份，导错了能退回
- 电脑端旧格式（v1 四文档信封）可以直接导入

## 目录

```
lib/
  core/       数据层与规则（纯 Dart，禁止 import Flutter）
  features/   业务逻辑（Workspace：全部业务规则）
  app/        应用装配与动作门面
  ui/         界面（手机外壳 + 各 Tab）
  platform/   平台适配（唯一允许出现平台判断 / 插件的地方）
docs/         计划、数据契约、构建说明
test/         契约样本回归、规则、存储、架构边界、界面冒烟
tool/         一次性脚本（启动图标生成）
```

电脑端那份归档工程已从工作区删除（省下约 263 MB），要翻旧代码用 git 历史：

```powershell
git show 786b143:archive/desktop-v1/lib/features/workspace.dart   # 单个文件
git ls-tree -r --name-only 786b143 -- archive                     # 归档里都有什么
```

分层边界由 `test/core/architecture_test.dart` 扫描源码守护。
