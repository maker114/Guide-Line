> **状态**：🟡 规划中，待用户确认 §6 的 6 个问题
> **前情**：电脑端成果已归档到 `archive/desktop-v1/`（136/136 测试通过、可打包）。

## 1. 为什么改方向

| 事实 | 推论 |
|---|---|
| 云端后端始终未定（LeanCloud 停服 → CloudBase 需套餐 → 阿里云 / 对象存储 / Git 私有仓库对比中） | 双端同步在任何方案下都**需要一个云端或一台常开设备** |
| 这是**单人自用**的生活管理工具，主要场景是**手机上随手速记** | 电脑端「深度编辑」的价值撑不起整套双端架构的复杂度 |
| 硬约束 C2「电脑不保证开机」 | 电脑不能当服务器；没有云就**根本没有同步**可言 |

**决定**：先做**纯手机（Android）单机应用**。同步降级为**将来的可选增强**
（数据模型与导出格式保留了这个口子，见 §4）。

## 2. 新的产品定义

| 项 | 结论 |
|---|---|
| 平台 | **Android**（用户机型：小米 15 Pro / HyperOS） |
| 形态 | **单机应用**：无账号、无网络依赖、无同步 |
| 数据 | 全部本地；**local-first 从"原则"变成"事实"** |
| 主要场景 | 速记灵感（一键直达）→ 分配到项目 → 合并进实现；事件与任务线的查看与勾选 |
| 次要场景 | 项目树整理、任务线展开、搜索、归档区清理 |

## 4. 数据与存储（待确认，见 §6-Q2）

单机后，原设计里为同步服务的东西都失去意义：

| 原设计 | 单机下 | 处置建议 |
|---|---|---|
| 4 份 JSON 文档分区（ADR-004 / 5.3） | 分区的唯一目的是**限制云端冲突范围**与**按文档推送** | 可合并为**单个文件**（见下） |
| 文档外层 `version` / `last_tx_id` | 无 CAS、无并发端 | 去掉 |
| `pending_tx`（跨文档事务重放） | 无网络，不存在"补发" | 去掉 |
| `sync_state.json` | 无账号 | 去掉 |
| `ui_prefs.json` | 视图偏好，改动频繁 | **保留为独立小文件**（避免为折叠一个节点重写整个数据文件） |
| 墓碑与墓碑骨架 | 单机下仍用于**回收站恢复** | 保留（Q33「不清理」也保留） |

### 推荐方案：**单文件 + 原子替换 + 备份轮转**

```
<应用私有目录>/guideline.json          ← 全部数据，一次原子 rename 写入
<应用私有目录>/guideline.backup.1.json ← 上一份（轮转保留最近 3～5 份）
<应用私有目录>/ui_prefs.json
```

理由：

1. **真正的本地原子性**：写临时文件 + rename 是"全有或全无"，跨实体的操作（合并灵感会同时改项目与灵感）
   不再需要"待完成事务"这种补偿机制；
2. **一份文件更好备份/分享**（导出即复制）；
3. 文件内部**按集合分区**，每个集合里的记录序列化格式**与现有契约完全一致**
   → 现有契约样本测试仍然有效（`docs/spec/数据契约.md` 只需改外层信封）。

```json
{
  "schemaVersion": 2,
  "savedAt": 1788652800000,
  "collections": {
    "projects":      { "items": [ /* 与契约逐字节一致的记录 */ ] },
    "inspirations":  { "items": [ ... ] },
    "events":        { "items": [ ... ] },
    "tasks":         { "items": [ ... ] }
  }
}
```

### 备份策略（**没有云端时这是头等大事**）

1. **写入即轮转**：每次成功写入前，把旧的 `guideline.json` 轮转为 `backup.1`（旧 1 → 2 → …，保留 5 份）
2. **手动导出 / 导入**：复用已归档的 `portability.dart`（`.json.gz`，含墓碑与骨架化对象，冲突不静默覆盖）
3. **分享出口**：导出的文件通过系统分享面板发到微信 / 网盘 / 邮件（Android 上插件不受"开发者模式"限制）
4. **到期提醒**：启动时若距上次导出 > 7 天，温和提醒一次（不做后台定时——Android 后台不可靠）

## 5. 范围

### 5.1 In（v1.0 必做）

- **灵感**：一键速记、编辑、分配到项目、上下分区合并、丢弃 / 恢复、删除
- **项目**：项目树（≤3 层）、目的 / 实现 / 日期、三态完成（含完成条件拦截与自动退回）、归档（级联）、删除（级联 + 二次确认显示影响范围）
- **事件与任务线**：事件增删改、主线标准任务、子任务、并列任务、到期日、勾选完成、逾期提醒、上移下移
- **归档区**：已归档 / 已丢弃 / 已合并 / 回收站 / 本地草稿 + 取消归档、恢复、撤销合并、彻底删除
- **聚合与检索**：今天 / 本周到期、全部任务、全局搜索
- **数据安全**：备份轮转、导出、导入、分享导出文件
- **Android 集成**：应用名与图标、**长按图标的「速记」快捷方式**（App Shortcuts）

### 5.2 Out（明确不做）

- 同步 / 账号 / 多端 / 云函数（**整个同步层与云端代码随归档搁置**）
- iOS（需 Mac + 开发者账号）
- 桌面小组件与通知栏常驻按钮 → **v1.1**（需要原生 Kotlin + `CaptureInbox` 文件通道）
- E2EE、附件、标签分类、多语言、端到端加密

## 8. 手机端信息架构（提案）

```
底部 Tab
├─ 灵感     速记输入框置顶 + 未处理列表（分配 / 合并 / 丢弃）
├─ 项目     项目树（可折叠）+ 详情页（目的 / 实现 / 日期 / 子项目 / 灵感）
├─ 事件     事件列表 → 任务线页（主线串联 + 子任务 + 并列任务）
└─ 更多     今天 / 本周到期 · 全部任务 · 搜索 · 归档区 · 备份与导出 · 设置

常驻：右下角「速记」FAB（灵感 Tab 内为输入框本身）
系统级：长按应用图标 → 「速记灵感」（App Shortcuts）
```

> 与电脑端"三栏 + 侧栏"的差异符合原设计 §3.1.1「手机端 Tab 导航、速记优先」的定位。
