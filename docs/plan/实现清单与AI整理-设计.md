# 设计：实现清单 · AI 整理 · 交接说明导出

> **状态**：设计已定（存储 / 是否联动任务 / 导出方式三项已确认），**代码未开工**。
> **前情**：「软件编辑」灵感整理的批次五。第 6 条原本只要求"分条展示"，
> 现在定的形态是**待办清单**；AI（第 15 条）随之变成两件事。
> 桌面小组件（第 16 条）**放弃，不做**。
> **整理时间**：2026-09-25

---

## 0. 三件事的定位

先说清边界，免得做出来互相打架：

| 功能 | 一句话 | 参与业务判定吗 |
|---|---|---|
| **实现清单** | 项目「实现」从一段纯文本变成**待办清单** | **不参与**。勾选只是打勾 |
| **AI 整理** | 把清单**反向压成**一段通顺的实现说明 | 不参与。结果落回文本 |
| **交接说明导出** | 把项目**导出成**一份 Markdown，丢给电脑上的 AI 去实现 | 不参与。纯导出 |

关键是第一行那条"不参与"：**清单条目与事件里的任务线彻底分开**。
任务有完成判定、有反向传播、有分叉合流；清单条目只是"这个项目打算怎么做"的备忘录。
两者混在一起会出现"项目里勾了、任务线那边没动"的矛盾，所以刻意不联动。

## 1. 实现清单（第 6 条）

### 1.1 数据：`Project.items`

契约 §3.2 新增字段（**追加在末尾，沿用"未设置即省略"**）：

| 字段 | JSON 类型 | Dart 类型 | 说明 |
|---|---|---|---|
| `items` | object[] | `List<ProjectItem>` | 空数组时**不写出**该字段 |

`ProjectItem` 的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | UUID v4，条目自己的身份（编辑、删除、排序都按它） |
| `text` | string | 非空（trim 后 ≥ 1） |
| `done` | bool | 勾选状态。**只表达"打勾了"**，不参与任何判定 |

三个刻意的决定：

- **顺序 := 数组下标**，不存 `order` 字段。任务那边存 `order` 是因为要跨父节点排序、
  还要兼容老数据的隐式链；清单就是个一维列表，数组本身的顺序就是顺序，
  再存一个 `order` 只会多一处能不一致的地方。
- **条目文本用 `readString` 而不是复用 `readStringList`**：后者会把空串丢掉，
  而清单里"文字被清空"应该由写入层拒绝（`RuleViolation`），不该静默消失。
- **`implementation` 字符串保留**，不删。它是 AI 整理与导出的**输入**，
  也是老数据的唯一存身之处。

### 1.2 老数据怎么办（零迁移）

分三种情形，**都不需要用户做任何事**：

| 老数据形态 | 读进来之后 | 界面上 |
|---|---|---|
| 有 `implementation` 文本、没有 `items` | `items` 为空，文本原样保留 | 清单区显示「还没有条目」+ 一个「从正文拆成条目」的动作 |
| 只有 `items`、文本为空 | 正常 | 正常清单 |
| 两者都有（AI 整理生成文本后） | 都保留 | 清单在上，整理后的正文在下（可折叠） |

**"从正文拆成条目"是一个显式动作，不在读取时自动拆。** 理由：
把一段中文按行拆开是不可逆的猜测（用户可能一段就是一条），
自动拆会在第一次打开时悄悄改写数据形态。给一个按钮，让用户自己按。

### 1.3 界面（项目详情页）

「实现」区从一个大文本框换成一个清单块：

```
实现                                    3/7 已完成
┌────────────────────────────────────┐
│ ☑ 冻结数据契约                      │
│ ☑ 补齐契约样本                      │
│ ☐ 写解析层                          │
│ ☐ 处理坏数据                        │
│ + 添加条目…                         │
└────────────────────────────────────┘
  [AI 整理成正文]  [导出交接说明]
```

- 勾选：点左边的框。**不写完成时间、不联动任何东西**（清单没有 `completed_at`）。
- 编辑：点文本原地改（复用 `InlineTextField`），空文本拒绝并恢复原值。
- 删除：右侧出现删除按钮（或左滑）。删除要二次确认吗？**不要** ——
  条目是轻量内容，误删重打一句就好，弹确认反而烦。
- 排序：第一版**不做拖拽**。加条目默认加在末尾；
  真需要调整顺序时用"上移 / 下移"两个小按钮（在动作菜单里），够用且不用引入拖拽库。
- 进度：`n/m` 只是展示，和项目的 `status` 无关 ——
  项目该不该算完成仍然由它自己的三态决定。

### 1.4 写入层 API（`Workspace`）

```
addProjectItem(projectId, text)            → ProjectItem
updateProjectItemText(projectId, itemId, text)
setProjectItemDone(projectId, itemId, done)
removeProjectItem(projectId, itemId)
moveProjectItem(projectId, itemId, delta)  // 上移 / 下移
splitImplementationIntoItems(projectId)    // 把正文按行拆成条目（显式动作）
```

约束：
- 文本空 → `RuleViolation`，保持原值；
- 值没变不写盘（存储层每次保存都重写整份文件并轮转备份）；
- `splitImplementationIntoItems` 只在**清单为空**时允许，避免把已有条目顶掉。

## 2. AI 整理（第 15 条 · 功能一）

### 2.1 做什么

把清单（+ 项目目的）交给模型，让它输出**一段协调的实现说明**，
写回 `implementation` 文本。**清单本身不动** —— 两者是"原始素材"与"整理稿"的关系。

方向与清单相反：清单是拆开，AI 整理是合起来。

### 2.2 联网边界（这是本应用第一次联网，逐条写死）

| 项 | 决定 |
|---|---|
| 请求发到哪 | 只有用户自己填的 `baseUrl`（默认 `https://api.deepseek.com`） |
| 发什么出去 | **项目标题 + 目的 + 清单条目文本**（含已勾选状态）+ 一段固定提示词 |
| **不发**什么 | 灵感原文、事件与任务、其它项目、导出记录、设备信息 —— 一律不发 |
| 凭据 | `apiKey` 存**应用私有目录**里的 `ai_config.json`（见 §4），不进 `ui_prefs.json`、不进导出 |
| 提示词与返回原文 | **不落盘**。只把用户确认后的结果写进 `implementation` |
| 开关 | 默认**关**。没配置 `baseUrl`/`apiKey` 时，界面上 AI 入口显示为"未配置" |
| 断网 / 超时 / 限额 | 超时 30 秒；失败给可读文案（"连不上 / 密钥不对 / 额度或限流"），**不留半截状态** |
| 呈现 | 返回结果**先给预览页**，用户确认或改完再写回；不直接覆盖现有正文 |

"AI 可能编造事实"这件事必须在界面上讲明白：预览页顶部放一句
**"模型可能补充或改写你没写过的东西，请逐句核对后再保存"**。

### 2.3 分层（必须遵守）

- `lib/core/` **纯 Dart、禁止 import Flutter**，所以 HTTP 客户端不进 core；
- `lib/platform/` 是**唯一允许出现插件与平台判断**的地方 → 网络调用放这里；
- 业务编排（组装 payload、解析返回、写回）放 `lib/features/`，
  通过一个**接口**依赖平台层，测试时注入假实现 —— 这样联网逻辑可被单测覆盖，
  不依赖真实网络。

依赖选择见 §4。

## 3. 交接说明导出（第 15 条 · 功能二）

### 3.1 触发与流程

「更多」或项目详情页 → **选一个项目** → 生成预览 → 导出：

1. 选中项目（就一个，不做多选 —— 一次交代一件事，AI 那边才抓得住重点）；
2. 生成 Markdown，**在预览页里显示全文**（可编辑，用户能删掉不想给出去的部分）；
3. 「导出为 .md」→ 写进导出目录 → 走已有的系统分享通道（与 `.json.gz` 导出同一套）。

### 3.2 内容与格式

```markdown
# 项目：<标题>

- 目的：<purpose>
- 标识色 / 日期 / 状态：（有才写）

## 实现清单

- [x] 已完成条目
- [ ] 未完成条目

## 整理后的实现说明

<implementation 正文，空则省略这一节>

## 待处理灵感

- 灵感文本

## 相关事件与任务线

### <事件名>

- [x] 主线任务（含子任务缩进、并列任务标注）
    - [ ] 子任务
```

几条格式决定：

- 任务列表用 **`- [x]` / `- [ ]`**（GitHub 任务列表语法）：丢给 AI 时最容易被读懂，
  粘进 GitHub issue 也能直接用。
- **只导出未完成的任务与子任务？不** —— 全导，已完成的打 `[x]`。
  AI 需要知道"已经做了什么"才能不重复建议。
- 空节**整节省略**，不要留一堆 `（无）`。
- 灵感只导 `pending`（已丢弃的不该再提；已合并的已经进了正文或清单）。

### 3.3 隐私提醒

预览页底部固定一句话：**"导出后文件会离开这台手机；请确认上面没有你不想外发的内容。"**
导出前不额外弹确认框 —— 预览页本身就是确认环节。

## 4. 依赖与凭据存储（**已定案**）

| 需要 | 定案 |
|---|---|
| HTTP | **`http` 包**（轻，易测） |
| 凭据 | **`flutter_secure_storage`**（Android 走 Keystore 加密） |
| 非敏感配置 | `baseUrl` / `model` 进 `ui_prefs.json`（跟背景图种子一个性质） |

**`apiKey` 与其余配置分开存**，这是本设计里最重要的一条：
`ui_prefs.json` 会进**滚动备份**、也会进**整库导出**（`ExportCodec` 打的是整份数据文件），
把 Key 放进去等于让它跟着备份和导出一起离开这台手机。

配套三条硬约束（测试逐条钉住）：

1. `ai_config` 相关的敏感值**只在安全存储里**，偏好 JSON 里连键都不出现；
2. 「更多 → 导出」的整库导出**不含** `apiKey`（它不在数据文件里，天然不含）；
3. 安全存储读取失败时**当作"未配置"**，不抛错、不崩界面 ——
   部分 ROM 上 Keystore 会偶发失败，那种情况给用户一句"还没配好"比抛异常更有用。

`AndroidOptions(resetOnError: false)` 是刻意开的：默认值会在解密异常时
**把已存的 Key 永久清掉**，而偶发失败更合理的处理是"这次读不出来"。

## 5. 契约与验证

- **契约变更**：`Project.items`（§3.2 字段表 + 样本 + 规格文档 + 兼容性测试**同一提交**）；
  `apiKey` **不进契约**、也不进 `ui_prefs.json` —— 它只存在系统安全存储里。
- **参考图/样本**：契约样本里给一个"有清单的项目"和一个"只有正文的老项目"，两种形态都覆盖。
- **测试**：
  - `test/core/`：条目的增删改勾选与上移下移、空文本拒绝、`items` 省略与逐字节往返、
    从正文拆分（含只有正文的老数据）、Markdown 生成（空节省略、勾选语法）；
  - `test/ui/`：清单能加条目、能打勾、能原地改、项目页入口点得到；
  - AI 编排层用**假平台实现**测：payload 里**不含**灵感与任务、失败不留半截状态、
    返回结果先预览再写回。
- **不做**：桌面小组件（已放弃）、清单条目的拖拽排序、多项目批量导出。
