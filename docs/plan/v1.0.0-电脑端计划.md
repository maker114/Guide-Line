# v1.0.0 电脑端（Windows）范围与计划

> 依据《双端软件架构设计》v13 与 §10 仓库规范。本文档是**电脑端优先**的落地计划。

---

## 1. 目标与验收（DoD）

**目标**：交付一个**可离线使用全部功能、可联网同步**的 Windows 桌面端，版本 **1.0.0**。

| 验收项 | 标准 |
|---|---|
| 版本号 | `pubspec.yaml` 为 `1.0.0+1`；标签 `v1.0.0`；CHANGELOG 定版 |
| 静态检查 | `flutter analyze` **0 issue**（含 3 条 import 边界 lint） |
| 测试 | `flutter test` 全绿；含数据契约逐字节比对与 `test/sync/` 守护测试 |
| 离线可用 | 断网可完成：创建/编辑/合并/删除/归档/搜索/导出；恢复网络后自动同步 |
| 数据安全 | 崩溃/断电后不丢已确认操作；`.tmp` 残留可自恢复；损坏文件不静默重建 |
| 同步 | 两端（桌面 + 后续手机）经 CloudBase 同步；跨文档操作**只调用一次** `commitTx` |
| 打包 | `flutter build windows --release` 产出可运行安装目录 |
| 合规 | `git status` 干净；提交信息符合 §10.3；CHANGELOG 按 §10.4 |

## 2. 范围

### 2.1 In（1.0.0 必做）

- **板块一**：项目树（≤3 层）、目的/实现/日期、三态、归档、灵感捕获/分配/合并（上下分区编辑）/丢弃/撤销合并
- **板块二**：事件、主线（标准任务兄弟链）、子任务、并列任务、三态、到期日与逾期标记、完成时间
- **完成规则**：判定域（墓碑/归档不参与）+ 自动退回
- **归档区**：已归档 / 已丢弃 / 已合并 / 回收站 / 本地草稿 + 彻底删除（二次确认）
- **聚合与检索**：今天/本周到期视图、全部任务视图、全局搜索（不含归档）
- **其他**：数据导出 / **导入**（`.json.gz`，含墓碑，冲突保留草稿）、Windows 托盘 + 全局快捷键速记、开机自启
- **同步**：`SyncBackend` 接口 + 假后端；**真实后端待定**（见 `docs/spec/云端后端选型对比.md`）
- **基础设施**：数据契约样本 + 回归测试、原子落盘、本地文件集、架构边界测试

> **重要变化（v1.0.0 范围收窄但更可交付）**：云端后端仍在对比中，而**零第三方方案已就位** ——
> 手动导出/导入（`lib/features/portability.dart`，10 个用例）使 1.0.0 成为
> **"单机完全可用 + 双端可手动搬移"** 的完整产品，不再以"选定云服务商"为前置条件。
> 云端一旦选定，只需在 `lib/sync/` 补一个实现类，UI 与业务层零改动。

### 2.2 Out（明确不做，记入 CHANGELOG 的 Unreleased 或后续版本）

- **异地自动同步**（必须依赖第三方服务或一台常开设备 —— 拓扑决定，非选型问题）
- 局域网直连同步（候选 H：需修订 ADR-026 与 §2.1 的"直连只用于加速读取"）
- 手机端（Android）外壳、系统级小组件/通知栏入口 → v1.1+
- iOS / macOS / Linux 平台 → 见 ADR-061
- E2EE（ADR-021）、附件/对象存储（ADR-012）、标签分类（Q43）、多语言（Q47）
- 到期系统通知（Q40）、推送唤醒（ADR-062）、墓碑物理清理（Q33）

## 5. 依赖与风险

| 项 | 状态 | 影响 | 处置 |
|---|---|---|---|
| **Flutter / Dart SDK** | ❌ 未安装 | **阻塞一切编译、测试、打包** | 需用户安装（见 §6）；沙箱内 HTTPS 被拦，无法自行下载 |
| Visual Studio 2022（C++ 工具集） | ✅ 已安装（Community） | — | 直接可用 |
| Node.js | ⚠️ 仅有 Adobe 捆绑的 **v16.13.2**（无内建 `node:test`，已用 `test/run.js` 规避） | 云函数逻辑测试可跑；**部署 CLI 与正式环境需要 Node 18+ LTS** | 装 Flutter 时顺手装 Node LTS（`nodejs.org` 或 nvm-windows） |
| CloudBase 环境（envId / Key） | ❌ 未开通 | 阻塞真实同步联调（M5 后半） | 先用假后端 + 契约测试推进；环境就绪后只替换实现 |
| CloudBase 默认域名限频 | ⚠️ 官方定位"开发测试" | 可能触发 `RATE_LIMITED` | 退避 + 状态可见；必要时绑定已备案域名 |
| 5 MB 单文档上限 | ⚠️ | 数据量增长后触发 | 监控文档体积，达阈值即启动 L2 迁移（设计文档 5.3） |
| 沙箱内 HTTPS 出网被拦 | ⚠️ | 影响 `pub get` 与 SDK 下载 | 由用户侧完成安装/首次 `pub get` |

## 6. 需要用户提供 / 执行

1. **安装 Flutter SDK**（Windows）：
   - 官方：`https://docs.flutter.dev/get-started/install/windows`
   - 大陆网络建议先设镜像环境变量：
     `PUB_HOSTED_URL=https://pub.flutter-io.cn`、`FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn`
   - 安装到 **D: 或 E:**（C: 仅剩约 16 GB）；把 `<SDK>\bin` 加入 PATH
   - 验证：`flutter doctor -v` 中 **Windows (desktop) 工具链为 ✓**
2. **CloudBase**：开通环境（腾讯云实名）后提供 `envId` 与 Publishable Key；
   云函数部署可稍后（M5 后半）。

## 7. 提交与文档纪律

- 每个里程碑**单独提交**，subject 用中文、动词开头、现在时、≤50 字符（§10.3）；
- 每次提交同步更新 `CHANGELOG.md` 的 `[Unreleased]`；
- 契约变更（数据契约 / 同步契约）**必须**在提交信息中说明，且与代码同一次提交；
- 新增 ADR 或推翻既有裁定 → 更新 `docs/architecture/双端软件架构设计.md` 并追加 ADR 编号。

## 8. 本地校验命令（不需要 Flutter SDK 的两道闸门）

```bash
node tools/check-contract-samples.js   # 契约样本：BOM / 换行 / 缩进 / key 顺序 / 结构 / 墓碑骨架
node tools/check-dart-contract.js      # Dart：括号平衡 + toJson 字段顺序 + knownKeys 与契约一致
cd cloudfunctions && node test/run.js  # 云函数逻辑：26 个用例（同步 13 + 身份 13）
```

> 这三条是**廉价前置检查**，不是编译器。`dart analyze` / `flutter test` 仍是最终判定。
> 命令行里若没有 Node 18+，可用任意 Node 14+（本机用 Adobe 捆绑的 v16.13.2）。
