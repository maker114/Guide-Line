## 一、已拍板、待实施

### Q1 项目取消「完成 / 搁置」，只靠归档
- **现状**：项目有三态（未完成 / 已完成 / 已搁置），界面有状态胶囊、完成图标、删除线、"还有 N 个子项目未处理"提示。
- **改成**：项目只表达"要 / 不要"；不需要了就归档。界面移除上述状态元素；往已完成项目里加内容这类连带问题一并消失。
- **老数据**：以前标过完成 / 搁置的标记**原样保留、不再显示**，零迁移。
- **连带作废**：原方案"父项目看最底层目标是否都终结"。
- **规模**：中 ｜ **契约**：不动（字段保留）

### Q2 子项目分两种角色：有下级 = 分类，没有下级 = 目标
- **现状**：子项目与主项目长得一样，都能写目的、列清单、定日期，用途不明。
- **改成**：分类行只显示名字、色条、汇总（`N/M 已完成`、含 N 个目标、待处理灵感 N 条）；不显示目的 / 实现计划 / 清单 / 日期 / 状态。新建入口随层级改名（根下"新建分类"、分类下"新建目标"）；灵感合并的落点只能是目标。
- **层级**：仍 ≤ 3 层；推荐"根（域）→ 分类 → 目标"。
- **依赖**：Q1（分类不再有状态，前提是项目整体取消三态）。
- **规模**：中 ｜ **契约**：不动

### Q3 保存拆成两件事：写数据照旧，备份只在离开页面时留
- **现状**：每个动作都整份写盘并轮转 10 份备份，改得勤就把老备份挤掉。
- **改成**：主文件仍然"改一下就存住"（防断电、防杀进程）；备份轮转按"页面会话 / 最小间隔"节流，一次页面操作只留一份。备份列表补上时间点与记录条数；覆盖性操作后提示"想反悔要尽快"。
- **规模**：中 ｜ **契约**：不动

### Q4 项目文案改名，并把"待办"只留给任务
- **改成**：「目的」→"有什么问题 / 思路"；「实现计划」→"如何解决"；界面上的"待办"一词只指事件里的任务，项目里的叫"清单"。

## 二、会丢数据 / 弄坏数据（建议优先）

### Q6 删项目的确认框改说真话
- **现状**：写着"全部可在回收站恢复"，但灵感**不进回收站**，删掉即找不回。灵感删除的说明又反过来让人以为"一点痕迹都没留"。
- **改成**：把灵感单独拆一句"这 N 条灵感会被永久删除，不进回收站"；灵感删除确认框补一句"备份与历次导出里可能仍有"。
- **另一种做法**：让灵感也进回收站（连带回收站页面、恢复逻辑都要改）。
- **规模**：小（改文案）/ 大（灵感进回收站）｜ **契约**：不动

### Q7 跨事件移动任务必须带走子任务
- **现状**：把一条主线任务"移到其它事件"时，子任务留在原事件 → 两个事件里都看不见它们，父任务永远勾不上（真 bug）。
- **改成**：移动时整棵子树一起搬；或禁止移动带子任务的节点，并说明原因。
- **规模**：中 ｜ **契约**：不动

### Q8 合并灵感时"正文没改"不算合并
- **现状**：在合并编辑器里直接点「保存」，正文一个字没变，灵感照样被标"已合并"、从灵感箱消失，项目里什么都没多。
- **改成**：正文与进入时完全一致就不执行合并，提示改用「追加原文」或「作为清单条目」。
- **规模**：小 ｜ **契约**：不动

### Q9 「撤销合并」改名或真撤销
- **现状**：入口叫"撤销合并"，实际只把灵感恢复为待处理，项目里写进去的内容不退回；再合并一次就重复。
- **改成**：改名"恢复为待处理（项目内容不会退回）"，或真的同步撤回写进去的那一行 / 那一条。
- **规模**：小（改名）/ 中（真撤销）｜ **契约**：不动

### Q10 归档项目与灵感列表的说法对齐
- **现状**：归档项目时承诺"这些灵感会从列表里隐藏"，实际灵感仍在灵感箱里；归档区又写着"因此不占用灵感列表"。
- **改成**：二选一 —— 灵感页真的隐藏（并提示"另有 N 条在已归档项目下"），或改文案说清它们仍在列表里。
- **规模**：小～中 ｜ **契约**：不动

### Q11 导出记账：取消分享不算导出
- **现状**：点导出后即使取消分享，"上次导出"也刷新，7 天内不再提醒；而文件还在应用私有目录里，卸载就没了。
- **改成**：区分"已导出到私有目录"与"已分享出去"；未分享不销掉提醒。
- **规模**：小 ｜ **契约**：不动

### Q12 回收站到期清理要吭声
- **现状**：30 天自动清除全程无提示；删除确认框不提期限；恢复提示只说"已恢复：X"，实际整条线一起回来。
- **改成**：启动清理非零时给一条可点提示；删除框补"30 天后自动清除"；恢复提示带上实际恢复条数与范围。
- **规模**：小 ｜ **契约**：不动

### Q13 导入前显示"你会少掉多少"
- **现状**：导入是整体替换，确认框只列"文件里有什么"，不列当前有多少、将减少多少。
- **改成**：并排列出"当前 N 条 / 文件 M 条 / 将减少 K 条"，并明说"合并"不支持（替代做法见 Q25）。
- **规模**：小 ｜ **契约**：不动

### Q14 AI「测试连接」不许偷偷保存
- **现状**：按钮旁边没说要保存，但点下去会把地址 / 模型 / 密钥一起落盘。
- **改成**：测试用临时配置不落盘；或在说明里补一句"会先保存上面的地址、模型与密钥"。
- **规模**：小 ｜ **契约**：不动

### Q15 AI 覆盖正文前留一份可退回的旧版
- **现状**：AI 整理会**覆盖**「实现计划」，只靠一句"原来那段可以先手动备份"。
- **改成**：覆盖前自动留一份旧正文，界面给"退回上一版"。
- **规模**：中 ｜ **契约**：不动（存本地偏好或专用备份）

### Q16 损坏恢复的告警要能用
- **现状**：主文件损坏自动恢复后只有一条不可点的小字，不说恢复了哪一份、隔离文件在哪；损坏也不刷新导出提醒。
- **改成**：告警条可点开，显示恢复来源与隔离文件名，并提供"先导出一份"；损坏时刷新导出提醒。
- **规模**：中 ｜ **契约**：不动

## 三、把数算对、口径统一

### Q17 事件进度只留一个算法
- **现状**：事件列表写「主线 2/4」，详情页写「主线 3/4 已完成」；一个把"搁置"算完成、一个不算，分母一个含已归档、一个不含。
- **改成**：两处共用同一个算法（分子含搁置、分母排除归档），文案统一为「N/M 已完成」。
- **规模**：小～中 ｜ **契约**：不动

### Q18 已归档任务的口径统一

- **改成**：任务线里给出明确的"已归档"标记（或不画）；计数与锁同一套数；归档区与搜索能按名字找回已归档的下级。
- **规模**：中 ｜ **契约**：不动

### Q19 逾期数字统一
- **现状**：横幅、角标、落点页面的分组头各算一批（是否排除已搁置事件 / 已归档任务不一致），用户对不上号；同一条搁置任务的日期颜色三处还不同。
- **改成**：三处共用一批任务；搁置任务的日期颜色统一（要么都不报警，要么都标明"不计入催办"）。
- **规模**：小～中 ｜ **契约**：不动

### Q20 「更多」页的副标题与页内数字同源
- **现状**：入口副标题用"含归档"算、页面用"排除归档"算；「12 条内容可搜（不含已归档）」与它自己的算法相反；归档区总数不含第五个页签；搜索命中超过 100 条仍写"100 条"。
- **改成**：副标题与页面共用同一个计数函数，文案的范围限定与算法一致；搜索加"只显示前 100 条"的说明。
- **规模**：小 ｜ **契约**：不动

### Q21 到期日写法统一
- **现状**：三套写法（只给相对日 / 绝对日期+剩余天数 / 窄屏降级），说明书里写的是"一律两个都给"。
- **改成**：默认"绝对日期 + 剩余天数"，仅窄屏降级为相对日；说明书与实现对齐。
- **规模**：小 ｜ **契约**：不动

### Q22 数量口径写进《界面规范》当唯一出处
- **内容**：标题栏只给数字（`项目 4`）；列表页统一"共 N 条"；进度统一 `N/M 已完成`；并要求"同一个数的分子分母同口径"。
