# 云端后端选型对比（待定）

> 背景：CloudBase 需套餐/兑换码，用户要求**尽量零成本**。本文把四条可选路线的**事实**摊开，
> 供对比决策。**注意**：无论选哪条，`lib/core`、契约、62 个测试、UI 都**不受影响** ——
> 差异只落在 `lib/sync/` 下的一个实现类（ADR-019 / ADR-064 的回报）。

状态：🟡 **待用户裁定**（裁定后写入 ADR，并替换/补充 ADR-048、ADR-069）

## 1. 硬性判定维度（来自设计文档第 1 章）

| 维度 | 要求 | 说明 |
|---|---|---|
| C1 无自建服务器 | 必须 | 托管 BaaS / Serverless / 托管存储；允许 Serverless 函数 |
| C2 电脑不保证开机 | 必须 | 电脑只能是客户端；云端必须是唯一真相源 |
| C5 国内可直连 | 必须 | 不依赖代理；延迟可接受 |
| 成本 | 目标零成本 | 单人、4 份 JSON、数千条记录、月增量极小 |
| 版本 CAS | 必须 | 写入必须能检测"我基于的版本已被改" |
| 跨文档原子性 | 强需求 | 合并灵感 / 删除项目会同时改两份文档（设计文档 5.9） |
| 隐私 | 关注 | 数据 = 全部个人记录；需私有空间 + 凭证保护 |
| 可用性 | 关注 | 偶发抖动可接受（本地优先，离线是一等公民） |

## 2. 四条路线的事实

### A. CloudBase 免费体验版
- **免费**：每个账号可用**一次性兑换码**（购买页领取）创建免费体验版环境，**3000 点/月**；
  单次续费 6 个月，**到期前 1 个月内可续**，不支持自动续费、不支持加购/按量。
- **国内直连**：✅（上海地域；文档型数据库**仅上海等地支持**，新加坡只支持 PG）
- **原子性**：✅ 云函数内数据库事务（已实现并实测 26/26）
- **服务端代码**：已写好（8 个云函数）
- **迁移成本**：**零**
- **风险**：续期政策可能变；免费环境有功能限制；需每半年手动续
- **来源**：[资源点价格文档](https://cloud.tencent.com/document/product/876/127357)（2026-09-15 更新）

### B. Gitee 私有仓库（国内）
- **免费**：私有无上限；需实名
- **国内直连**：✅ 最稳
- **原子性**：⚠️ 单文件写入可带 `sha`（= CAS）；**多文件一次提交需实测**（若不支持 →
  退化为顺序写 + `pending_tx` 幂等重放，正是 A3 你选的机制）
- **服务端代码**：❌ 不需要（整个 `cloudfunctions/` 可删）
- **迁移成本**：新增一个 `SyncBackend` 实现；身份层简化为"仓库令牌即凭证"
- **优点**：版本历史天然可回溯；无需公网 IP/域名/备案
- **风险**：API 限流较严；仓库体积随提交历史增长（需周期性压缩）

### C. GitHub 私有仓库
- **免费**：私有仓库无上限
- **国内直连**：⚠️ 通常可达，偶发慢/抖动
- **原子性**：✅ **最强** —— Git Data API（blob → tree → commit → 更新 ref）；
  ref 非快进更新返回 422，**本身就是乐观锁**；重试时若 HEAD 已含本次改动即幂等
- **服务端代码**：❌ 不需要
- **迁移成本**：同 B
- **风险**：数据出境；大陆访问稳定性

### D. 对象存储（腾讯云 COS / 阿里云 OSS）
- **免费**：严格说是按量付费；但 2 MB 数据 + 少量请求 ≈ **每月不到 1 分钱**（非"零成本"）
- **国内直连**：✅
- **原子性**：⚠️ 条件写语义弱（COS `x-cos-forbid-overwrite` 只能"不存在才创建"），
  需自行拼"版本号文件名 + 指针对象"；或完全依赖 `pending_tx`
- **服务端代码**：❌ 不需要
- **风险**：CAS 语义要靠自己拼，容易出隐蔽竞态

### 已排除
| 方案 | 排除原因 |
|---|---|
| Supabase 免费版 | 大陆直连不稳定 + 数据出境 |
| Cloudflare Workers/D1 | `workers.dev` 在大陆基本不可用，需自定义域名 + 备案，不满足"零成本" |
| 自建服务器 | 违反 C1 |
| 局域网直连 / 电脑做中转 | 违反 C2（ADR-026） |
| 网盘同步文件夹 | 文件级同步互相覆盖（ADR-005） |
| 阿里云盘开放平台 | 无 CAS/条件写语义，且需开发者审核，不适合做同步层 |

## 2.5 修正：对象存储其实够用（E / F 两条阿里云路线）

**上一版把 D（对象存储）评为"条件写语义弱"，这个判断偏保守了。** 已核实：

> OSS `x-oss-forbid-overwrite: true` —— 同名对象已存在时**拒绝上传**并返回 `FileAlreadyExists`
> （[官方文档](https://help.aliyun.com/en/oss/developer-reference/prevent-objects-from-being-overwritten-by-objects-that-have-the-same-names)），
> simple upload 与 multipart 都支持。腾讯云 COS 的 `x-cos-forbid-overwrite` 语义一致。

于是可以**不写服务端**就拿到真正的乐观锁：

```
写入文档 N+1：PUT  doc/<name>/v<N+1>.json   + x-oss-forbid-overwrite: true
  · 成功                    → 提交成功
  · FileAlreadyExists       → 有人已经写了 v<N+1> → 冲突（若 txId 相同则视为幂等成功）
读取：LIST doc/<name>/ → 取最大版本号（ListObjects 很便宜），无需"指针对象"，避免指针竞态
跨文档：不原子 → 由**已实现的 pending_tx + 幂等重放**保证最终一致（正是 A3 用户裁定）
历史：旧版本对象天然保留，可回滚到任意版本；定期清理可选
```

### E. 阿里云 OSS（推荐给"零服务端 + 成本≈0"）
- **免费度**：无永久免费额度，但 2 MB 数据 + 每月几千次请求 ≈ **每月不到 1 分钱**
- **国内直连**：✅
- **CAS**：✅ 见上（版本化对象名 + forbid-overwrite）
- **跨文档原子性**：⚠️ 靠 `pending_tx` 幂等重放（已实现并有测试）
- **服务端代码**：❌ 不需要 —— **`cloudfunctions/` 整个可删**
- **凭证**：客户端需 OSS 凭证，两种取法：
  1. 用户在设置里粘贴**RAM 子账号 AK**（策略限定到单 bucket 单前缀）→ 存 Windows 凭据管理器，不硬编码；
     配对 = 第二台设备粘贴同一 AK。⚠️ 长期凭证，权限大于 STS
  2. 用 FC 签发 STS 临时凭证（更安全，但等于又引入服务端）
- **实现成本**：`OssSyncBackend` ≈ 200 行（含 OSS Signature V1 签名，HMAC-SHA1 手写，**无第三方依赖**）+ 测试
- **风险**：OSS 侧需自己维护版本清理；写路径是"先创建对象"，失败会留下孤儿对象（无害）

### F. 阿里云 函数计算 FC + 表格存储 OTS
- **免费度**：FC 有免费额度（额度以官网为准），OTS 按量计费、成本同样极低
- **国内直连**：✅
- **CAS**：✅ OTS **行级条件更新**（原生原子）
- **跨文档原子性**：✅ 服务端可保证
- **服务端代码**：✅ 需把现有 8 个云函数改写成 FC handler + OTS 存储层
- **凭证**：客户端只拿 FC 签发的临时 STS → 安全性最好（不落地长期密钥）
- **风险**：工作量比 E 大一截；两套 SDK 都要换

### G. 阿里云 EMAS Serverless（形态最接近 CloudBase）
- 云函数 + 文档型数据库 + 用户认证，有免费额度（现状与额度需核实）
- ⚠️ Flutter 端接入方式与 SDK 迁移成本最高，暂不推荐优先尝试

## 3. 我的建议（按性价比排序）

1. **E（阿里云/腾讯云 对象存储 + 版本化对象）** —— **零服务端、成本≈0、无兑换码无续期**；
   唯一取舍是凭证形态（自持受限 RAM AK vs 引入 FC 签 STS）。
   对"单人自用、数据是自己的、策略可限定到单前缀"的场景，性价比最高。
2. **A（CloudBase 免费体验版）** —— 零改动、原子性最好、国内直连最稳；
   代价是每半年续一次、政策存在变数。**若兑换码容易拿到，这是最快把真实同步跑通的一条。**
3. **B（Gitee）** —— 若要"永久免费、不看政策脸色"且不要长期 AK（用仓库令牌），这条最稳；
   代价是原子性依赖 `pending_tx`。
4. **F（FC + OTS）** —— 要"客户端不落地长期密钥 + 服务端原子性"就选它，代价是工作量最大。
5. **C（GitHub）** —— 技术最优雅（真原子提交 + 可回溯），但要接受数据出境与偶发抖动。
6. **D / G** —— 仅在上述都不可行时考虑。

## 3.5 零第三方方案（H / I）

### 先说物理限制

> **"异地自动同步"在不依赖任何第三方的前提下无法实现。**
> 要么有一台**常开的**设备（NAS / 旧手机 / 迷你主机 —— 那实质上就是自建服务器，违反 C1 字面约定），
> 要么借用第三方服务。这是拓扑决定的，不是选型问题。
>
> 因此"不依靠第三方"可选的只有下面两条，且它们都**只能覆盖"两个设备彼此可达"的时机**。

### H. 局域网直连同步（未实现，可实现）

- **机制**：两端在同一 Wi-Fi 时，一端临时起 HTTP 端点，另一端作为客户端对账；
  本质是**再实现一次 `SyncBackend`**，只不过"后端"是另一台设备。
- **零第三方**：✅ 数据不经任何服务器（`127.0.0.1` 与局域网地址）
- **冲突**：复用既有冲突流程（保留草稿，绝不静默丢）
- **配对**：一次性配对码 / 二维码（含 `http://192.168.x.x:<port>` + 一次性 token）
- **实现成本**：约 2 天（`dart:io` 的 `HttpServer` + UDP 广播发现 + 一次性配对 + 测试）
- **必须修订的既有裁定**：**ADR-026（两端不直连）** 与 §2.1 的「直连只用于加速读取，写入仍走云端」——
  在无云端的前提下，直连会成为唯一写入通道，需要新的冲突语义（目前是"整份文档 + 人工选择"）。

### I. 手动导出 / 导入（✅ **已实现并有测试**）

- **机制**：A 导出 `guideline-export-<时间>.json.gz` → 用 U 盘 / 蓝牙 / 微信发文件 → B 导入并合并
- **零第三方**：✅ 文件靠你自己搬
- **已实现**：`lib/features/portability.dart`（10 个用例，含 gzip 往返、墓碑不复活、
  冲突不静默覆盖、冲突草稿分离）
- **判定规则**：payload 相同 → 对齐版本；本地有未提交改动 → **冲突**（不静默覆盖）；
  版本高者胜；**版本相同且本地干净 → 采用导入包**（离线搬移时两端版本号常常都是 0，这是主路径）
- **成本**：0；**无任何外部依赖、无凭证、无续期**

### 结论

**v1.0.0 不再以"选定云服务商"为前置条件**：I 已经让产品成为
「单机完全可用 + 双端可手动搬移」的闭环。云端（A/B/C/E/F）与局域网直连（H）
都是**可选增强**，且都只影响 `lib/sync/` 下新增一个实现类。

## 4. 决策时需要你提供的凭证（各路线）

| 路线 | 需要你给我的东西 | 隐私注意 |
|---|---|---|
| A | `envId` + Publishable Key（Secret 不要给） | — |
| B | 私有仓库地址 + 令牌（**只给仓库范围的令牌**，用完可吊销） | 令牌 = 全部数据凭证，等同密码 |
| C | 同 B（建议 fine-grained PAT，仅 Contents 读写 + 仅该仓库） | 同上 |
| **E（OSS）** | Bucket 名 + 地域 + RAM 子账号 AK（**策略限定到单 bucket 单前缀**） | 长期凭证，建议单独建子账号、只授该前缀、可随时吊销 |
| **F（FC+OTS）** | FC 服务地域 + OTS 实例名；部署用的 AccessKey（用完可删该 AK） | 客户端最终只拿 STS 临时凭证，长期密钥不落地 |

> 凭证一律**不写进仓库**：客户端存系统凭据管理器（`sync_state.json` 只存 accountId 等非敏感标识），
> 云端存函数环境变量（见设计文档 §7）。
>
> **E 路线的推荐做法**：单独建一个 RAM 子账号（如 `guideline-sync`），
> 只授 `oss:PutObject / GetObject / ListObjects` 于 `acs:oss:*:*:<bucket>/guideline/*`，
> 并把该 AK **手工填进 App 设置页**（不随安装包分发）。
