# 同步与云函数契约

> 依据《双端软件架构设计》v13 的 §5（同步机制）、§6.1（CloudBase）、§7（安全与凭证）编写。
> 状态：✅ 定稿（对应 ADR-048 / 049 / 050 / 064 / 066）

---

## 0. 一句话结构

```
Flutter 客户端 ──(cloudbase_flutter SDK：仅认证 + callFunction)──> 云函数（唯一写入口）
                                                                    │
                                                            文档型数据库 documents 集合
```

**客户端不直连数据库**（ADR-064）。API Key 仅用于公开资源；所有业务读写经云函数，
`accountId` 一律取自会话，**不接受客户端传入**。

---

## 1. 本地文件清单

| 文件 | 参与同步 | 内容 |
|---|---|---|
| `projects.json` / `inspirations.json` / `events.json` / `tasks.json` | ✅ | 完整文档外层（见《数据契约》§2），与云端逐字节同构 |
| `sync_state.json` | ❌ | `{ schemaVersion, accountId, firstSyncDone, lastSyncAt }` |
| `pending_tx.json` | ❌ | 待完成事务（见 §5） |
| `ui_prefs.json` | ❌ | 视图偏好（折叠集合等，ADR-059） |
| `conflicts/conflict_<doc>_<ts>.json` | ❌ | 冲突草稿（设计文档 5.10） |
| `capture_inbox.json` | ❌ | 系统级入口投递文件（含 `capture_id` 幂等，设计文档 6.3） |

**落盘必须原子**：写 `<name>.tmp` → `fsync` → `rename` 覆盖；启动时忽略并删除残留 `.tmp`。
**关键操作立即落盘**（合并、删除、归档、批量移动、彻底删除），不等 1~2 秒防抖。

## 2. `SyncBackend` 接口（Dart 草案，`lib/sync/sync_backend.dart`）

```dart
/// 四份文档的名字（与本地文件名一致）
enum DocName {
  projects('projects.json'),
  inspirations('inspirations.json'),
  events('events.json'),
  tasks('tasks.json');

  const DocName(this.fileName);
  final String fileName;
}

/// 版本探测结果
class DocMeta {
  const DocMeta({required this.version, required this.updatedAt});
  final int version;
  final int updatedAt;
}

/// 整包读取结果。payloadJson 是**原始 JSON 字符串**，接口层不解码业务字段。
class DocSnapshot {
  const DocSnapshot({
    required this.name,
    required this.version,
    required this.updatedAt,
    required this.payloadJson,
  });
  final DocName name;
  final int version;
  final int updatedAt;
  final String payloadJson;
}

/// 一次事务中要提交的单份文档
class TxDoc {
  const TxDoc({required this.name, required this.baseVersion, required this.payloadJson});
  final DocName name;
  final int baseVersion;   // == 本地该文档当前 version
  final String payloadJson;
}

class TxRequest {
  const TxRequest({required this.txId, required this.docs});
  final String txId;       // UUID v4，幂等键
  final List<TxDoc> docs;  // 1..4 份；跨文档变更必须一次给全
}

/// 提交结果：成功或冲突（不抛异常，便于上层做 UI 决策）
sealed class CommitOutcome {
  const CommitOutcome();
}

class Committed extends CommitOutcome {
  const Committed(this.versions);
  final Map<DocName, int> versions; // 提交后的新版本号
}

class Conflict extends CommitOutcome {
  const Conflict(this.remoteVersions);
  final Map<DocName, DocMeta> remoteVersions;
}

class BackendFailure implements Exception {
  const BackendFailure(this.code, this.message, {this.retryable = false});
  final BackendErrorCode code;
  final String message;
  final bool retryable;
}

enum BackendErrorCode { unauthenticated, network, rateLimited, notFound, invalid, internal }

abstract interface class SyncBackend {
  /// 建立/恢复会话：首次注册或恢复码换票；已登录则直接返回
  Future<Account> ensureAccount();

  /// 设备配对（次端用一次性配对码换取同一 accountId 的会话）
  Future<Account> pairWithCode(String pairingCode);

  /// 只读元数据，供轮询探测（几百字节）
  Future<Map<DocName, DocMeta>> getVersions();

  /// 读取整包
  Future<DocSnapshot> getDoc(DocName name);

  /// 唯一写入口：CAS + 写入 + version+1 + last_tx_id
  Future<CommitOutcome> commitTx(TxRequest request);
}

class Account {
  const Account({required this.accountId, required this.deviceId});
  final String accountId;
  final String deviceId;
}
```

**硬约束**

1. `payload` 以**字符串**穿过接口层，序列化只由 `lib/core` 负责 —— 避免二次编解码改变字节形态（契约风险）。
2. `SyncBackend` 的实现**只能出现在 `lib/sync/cloudbase/`**；`lib/core`、`lib/features` 禁止 import CloudBase SDK 类型（ADR-019 / ADR-064，由 lint 守护）。
3. 接口只有 5 个方法。新增能力必须先改本契约。

## 3. 云端数据模型（CloudBase 文档型数据库）

| 集合 | `_id` | 字段 | 说明 |
|---|---|---|---|
| `documents` | `"<accountId>:<docName>"` | `accountId`, `name`, `version`, `updated_at`, `last_tx_id`, `payload` | 4 条/账号；`payload` 对云函数**不透明** |
| `accounts` | `accountId` | `recoveryHash`(sha256+salt), `createdAt`, `lastSeenAt` | 恢复码只存哈希 |
| `devices` | `"<accountId>:<deviceId>"` | `accountId`, `deviceId`, `name`, `lastSeenAt`, `revoked` | 可单独吊销 |
| `pairing_codes` | `code` | `accountId`, `expiresAt`(TTL 5min), `used` | 一次性 |

**权限**：客户端不具备数据库直连权限；云函数校验会话 → 取出 `accountId` → 强制拼 `_id`。
**索引**：`documents(accountId, name)` 唯一；`pairing_codes(expiresAt)` TTL。

## 4. 云函数契约（6 个）

> 统一约定：入参/出参均为 JSON；错误一律返回 `{ ok: false, code, message }`（HTTP 200 + 业务错误码，避免 SDK 抛网络异常掩盖业务错误）；
> 所有函数首行校验会话，`accountId` **不可**作为入参。

### 4.1 `commitTx`（唯一写入口）

请求
```json
{
  "txId": "uuid-v4",
  "docs": [
    { "name": "projects.json",     "baseVersion": 12, "payload": { "items": [] } },
    { "name": "inspirations.json", "baseVersion": 9,  "payload": { "items": [] } }
  ]
}
```

响应（成功）
```json
{ "ok": true, "versions": { "projects.json": 13, "inspirations.json": 10 } }
```

响应（冲突）
```json
{ "ok": false, "code": "CONFLICT",
  "remote": { "projects.json": { "version": 14, "updatedAt": 1735000000000 } } }
```

行为
1. 在**数据库事务**内逐份读取当前 `version`（设计文档 5.9）；
2. 全部等于 `baseVersion` → 写入 + `version+1` + `updated_at = 服务端时间` + `last_tx_id = txId`，提交；
3. **幂等**：若某文档 `version != baseVersion` **且** `last_tx_id == txId` → 视为该事务已成功，返回 `ok`（不重复 +1）；
4. 任一文档冲突 → 回滚全部，返回 `CONFLICT` 与冲突文档的远端版本；
5. 限制：单事务 ≤ 100 次操作 / ≤ 30 秒（CloudBase 事务上限）；
6. `payload` 原样存储，**不做任何字段校验或改写**。

### 4.2 `getVersions`

```json
→ {}
← { "ok": true, "docs": { "projects.json": { "version": 13, "updatedAt": … }, "…": { … } } }
```
只返回元数据。**轮询只能调用它**（设计文档 5.5 的流量约束）。

### 4.3 `getDoc`

```json
→ { "name": "tasks.json" }
← { "ok": true, "name": "tasks.json", "version": 12, "updatedAt": …, "payload": { "items": [] } }
```

### 4.4 `registerAccount`（首端初始化）

```json
→ { "recoveryCode": "24 字符 Base32（剔除 0/O/1/I）", "deviceId": "uuid", "deviceName": "Windows PC" }
← { "ok": true, "accountId": "uuid", "ticket": "custom-ticket" }
```
- 服务端生成 `accountId`；**恢复码只存 `sha256(salt + code)`**；
- 返回的 `ticket` 由客户端交给 SDK 完成自定义登录；`ticket` 有效期 ≤ 5 分钟，单次可用。

### 4.5 `pair`（次端配对）

```json
→ { "code": "6 位数字", "deviceId": "uuid", "deviceName": "Android" }
← { "ok": true, "accountId": "uuid", "ticket": "custom-ticket" }
```
- `code` TTL 5 分钟、**单次有效**；失败不区分"码错误"与"码过期"（防枚举）；
- 同一账号连续失败 5 次 → 该账号配对功能冷却 10 分钟。

### 4.6 `issueTicket`（恢复码换票）

```json
→ { "accountId": "uuid", "recoveryCode": "…", "deviceId": "uuid", "deviceName": "新电脑" }
← { "ok": true, "ticket": "custom-ticket" }
```
- 校验哈希；失败返回统一错误码 `UNAUTHENTICATED`；
- 连续失败按指数退避 + 冷却（恢复码是高价值凭证）；
- 成功后写入/更新 `devices`，并把旧设备的会话标记为待复核（可选提示）。

**另需一个管理端云函数**（默认关闭）：`rotateRecoveryCode`（重新生成恢复码，旧码立即失效）。

## 5. 待完成事务（`pending_tx.json`）

```json
{
  "txId": "uuid-v4",
  "createdAt": 1735000000000,
  "docs": [ { "name": "projects.json", "baseVersion": 12 } ],
  "retry": 0,
  "lastError": null
}
```

规则（设计文档 5.9）

- 任何**跨文档**操作在「改内存 → 置 dirty」的同一时刻写入本文件；
- payload 不重复存储（仍在内存与 4 份文档中）；
- 提交成功 → **立即删除**；
- 失败 → 下次同步**优先补发**，`retry >= 3` 时在 UI 暴露「有 1 个未完成事务」并允许手动重试；
- 启动时若发现残留 → **先补发再拉取**；
- ❌ 禁止任何跨文档操作退化为两次独立提交 —— 由 `test/sync/` 守护测试断言。

## 6. 同步状态机与流程

```
idle ──trigger──> replaying(有 pending_tx?) ──> pushing(dirty 文档) ──> pulling ──> idle
                                   │                    │                 │
                                   └── 失败 ────────────┴──── 失败 ───────┴──> error(可重试/不可重试)
```

固定顺序

1. 有残留 `pending_tx` → 先补发（失败即终止本轮）；
2. 对每个 dirty 文档 → `commitTx`（单文档也是长度 1 的事务）；
   - 成功 → 清 dirty、写回新 `version`；
   - `Conflict` → 进入冲突流程（§7），本轮不再推送该文档；
3. `getVersions` 探测 → 仅对 `version > 本地` 的文档 `getDoc` 并整体替换；
4. 落盘 `sync_state.json`。

**触发时机**（设计文档 5.5）：App 启动 / 切回前台 / 手动刷新 / 网络恢复 /
Android WorkManager（≥15min）/ Windows 托盘常驻 5 分钟轮询。
**不做**推送唤醒（ADR-062）。

**退避策略**：网络类错误 2s → 5s → 15s → 60s（上限 5 分钟）；`rateLimited` 按服务端返回的等待时间；
`unauthenticated` 立即停止并提示重新配对/恢复，不重试。

**UI 必须暴露的状态**（设计文档 §2 的「状态可见」原则）：
`已同步(vN, 时间)` / `同步中` / `离线(本地已保存)` / `有未完成事务` / `冲突待处理`。

## 7. 冲突处理

| 情况 | 判定 | 处理 |
|---|---|---|
| 本地无 dirty，云端版本更高 | 正常更新 | 整体替换 |
| 本地 dirty，`commitTx` 返回 `CONFLICT` | 真冲突 | 弹窗：以云端为准 / 以本地为准 |
| 选「以云端为准」 | — | 未推送内容**先写** `conflicts/conflict_<doc>_<ts>.json`，再整体替换 |
| 选「以本地为准」 | — | 用远端最新 `version` 作为新 `baseVersion` 重推一次 |
| `last_tx_id == txId` 且版本不等 | 伪冲突（响应丢失） | 按成功处理（幂等） |

**不做**：字段级合并、CRDT、history 表、自动合并（设计文档 5.6）。

## 8. 错误码表

| code | 含义 | 客户端行为 |
|---|---|---|
| `UNAUTHENTICATED` | 会话无效 / 恢复码错误 | 停止同步，引导重新配对或恢复 |
| `FORBIDDEN` | 越权（非本人 accountId） | 记日志并停止（不应发生） |
| `CONFLICT` | 版本不匹配 | 冲突流程 |
| `NOT_FOUND` | 文档尚未创建 | 以 `version = 0` 建立基线 |
| `RATE_LIMITED` | 默认域名限频 / 事务过频 | 按提示退避（设计文档 6.1 风险 1） |
| `INVALID` | 入参非法（payload 过大等） | 不重试，暴露错误 |
| `INTERNAL` | 云函数异常 | 可重试，指数退避 |

**payload 体积上限**：单文档 ≤ 5 MB（设计文档 5.3 的 L2 升级触发条件之一）；超限直接 `INVALID`。

---

## 9. 安全与日志

1. 恢复码 / ticket / 会话令牌**禁止**写入日志、crash 报告或普通配置文件；
2. 会话存 **Windows 凭据管理器**（手机端为 Keystore / Keychain）；
3. 云函数日志只记录：`accountIdHash`（前 8 位）、`txId`、`docName`、`version`、耗时、错误码；**禁止记录 payload**；
4. 客户端内置配置仅 `envId` + Publishable Key；
5. 所有请求 HTTPS；
6. 恢复码丢失 = 数据无法通过任何合法路径取回 —— UI 必须给出最高级别提示。
