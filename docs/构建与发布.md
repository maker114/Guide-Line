# 构建与发布

手机端（Android 单机版）的构建流程。命令都在**仓库根目录**执行。

## 1. 依赖环境

| 组件 | 版本（本机实测） | 说明 |
|---|---|---|
| Flutter | 3.47.5（Dart 3.13.4） | 装在 `E:\flutter` |
| Android SDK | Build-Tools 36 / Platform 35 / CMake 3.22.1 | 首次构建时由 Flutter 自动下载 |
| JDK | 随 Android Studio 安装 | Gradle 用 |

## 2. 日常命令

```powershell
flutter analyze --no-pub   # 静态检查，必须 0 问题
flutter test               # 全部测试，必须全绿
flutter build apk --release
```

产物：`build/app/outputs/flutter-apk/app-release.apk`（约 50 MB）。

> **在自动化 / 管道环境里跑 Flutter 命令时**，把输出重定向到文件再读，
> 否则 `flutter` 的进度输出可能把调用方卡住。

## 3. 启动图标

图标是**代码生成**的，不维护二进制素材：

```powershell
dart run tool/make_launcher_icons.dart
```

脚本按 4× 超采样自绘并手写 PNG 编码，输出五个密度的
`android/app/src/main/res/mipmap-*/ic_launcher.png`。
改图形只需要改脚本里的 `_onMark`（图案）与 `_gradientTop/_gradientBottom`（配色）。

## 4. 首次构建：Gradle 发行包可能下载卡住

`android/gradle/wrapper/gradle-wrapper.properties` 指向
`https://services.gradle.org/distributions/gradle-9.3.1-all.zip`（约 224 MB）。
本机实测 **Gradle 自带的下载器会卡在 0 字节**（同一时刻用浏览器/curl 拉同一 URL 却能跑满带宽）。

绕过办法：手动把发行包预置到 wrapper 期望的位置，Gradle 会自己校验并解压。

```powershell
$d = "$env:USERPROFILE\.gradle\wrapper\dists\gradle-9.3.1-all\9ot9r568e8zfvvd4mn8rbu1j0"
Remove-Item "$d\*.lck","$d\*.part" -Force -ErrorAction SilentlyContinue
curl.exe -L -o "$d\gradle-9.3.1-all.zip" `
  https://mirrors.cloud.tencent.com/gradle/gradle-9.3.1-all.zip
```

> `9ot9r568e8zfvvd4mn8rbu1j0` 是 Gradle 按 distributionUrl 算出来的目录名，
> 换 Gradle 版本时会变；先跑一次 `flutter build apk` 让它把目录建出来即可。
>
> 这只是**本机环境问题**，不是项目问题，所以仓库里的 `distributionUrl` 保持官方地址不动。

## 5. 另一个环境坑：Kotlin 增量编译缓存

本机（Windows + 仓库路径含空格）上，插件的 Kotlin 增量缓存会在 `compileReleaseKotlin`
结束时写不进去：

```
Execution failed for task ':android_file_picker:compileReleaseKotlin'.
> Could not close incremental caches … class-fq-name-to-source.tab, source-to-classes.tab
```

删掉 `build/` 也复现，属于环境问题。因此 `android/gradle.properties` 里关掉了增量编译：

```properties
kotlin.incremental=false
```

代价只是插件模块每次全量编译（本工程只有两个插件，影响很小）。**不要**为了提速把它改回 `true`。

## 6. 装到手机上

release 包的签名有两条路（S-4）：

- **没有 `android/key.properties` 时**：用 Flutter 模板默认的 debug 签名，直接侧载即可（老行为，不变）。
- **有 `android/key.properties` 时**：用正式 keystore 签名。`build.gradle.kts` 会自动改用它。

要换成正式签名，在 `android/` 下建 `key.properties`（**已在 .gitignore 里，绝不入库**）：

```properties
storeFile=../keys/guideline.jks
storePassword=...
keyAlias=guideline
keyPassword=...
```

> ⚠️ **换签名要趁早**：签名不同，Android 会**拒绝覆盖安装** —— 已装 debug 签名包的用户
> 必须先卸载，而卸载会连应用私有目录里的数据一起删掉（只能靠导出 / 备份找回）。
> 参考生成命令：`keytool -genkey -v -keystore guideline.jks -keyalg RSA -keysize 2048 -validity 10000 -alias guideline`

侧载：

```powershell
adb install -r build\app\outputs\flutter-apk\app-release.apk
```

或者把 APK 拷到手机上，在「设置 → 应用 → 安装未知应用」里允许文件管理器安装。

### 6.1 真机上怎么验证

**小米 15 Pro（HyperOS / Android 16）不允许 adb 注入输入事件**：

```powershell
adb -s 51dabb34 shell input swipe 540 1800 540 1200 300
# java.lang.SecurityException: Injecting input events requires ... INJECT_EVENTS permission
```

`input tap` / `input swipe` / `input keyevent` **全部**被这一条挡住（2026-09-25 复测确认）。

所以两条路分开走：

| 想验的东西 | 在哪验 | 怎么驱动 |
|---|---|---|
| 点击、滑动、输入法联动等**交互流程** | Android 15 模拟器（`emulator-5556`，`input tap/swipe` 可用） | adb 注入坐标 |
| **真机上的 IME 行为、启动路径、升级后数据是否还在** | 小米 15 Pro | 应用自己的 Intent + 截图 |

真机上能做的三件事：

```powershell
# 1) 冷启动速记路径（长按图标速记走的是同一个 action）
adb -s 51dabb34 shell am force-stop com.maker.guideline
adb -s 51dabb34 shell am start -a com.maker.guideline.SHORTCUT_CAPTURE -n com.maker.guideline/.MainActivity

# 2) 键盘到底弹没弹（**不要只看截图**，这里踩过一次：截图看着像弹了）
adb -s 51dabb34 shell dumpsys input_method | Select-String mInputShown

# 3) 看界面 / 确认版本与数据还在
adb -s 51dabb34 shell screencap -p /sdcard/p.png
adb -s 51dabb34 pull /sdcard/p.png shot.png
adb -s 51dabb34 shell dumpsys package com.maker.guideline | Select-String versionName
```

> `screencap` 的输出**必须**走「手机存文件 → `adb pull`」。
> 在 PowerShell 里 `adb exec-out screencap -p > x.png` 会被按文本重写换行，得到的 PNG 是坏的。

### 6.2 升级安装与验收（2026-09-25 实测记录）

从 **1.1.0+2 升到 1.3.0+4**（跨了 1.2.0），全程无人值守、**老数据零迁移**：

```powershell
flutter build apk --release --build-name=1.3.0 --build-number=4   # 见 §6.4，必须显式给版本
adb -s 51dabb34 install -r build\app\outputs\flutter-apk\app-release.apk
adb -s 51dabb34 shell am force-stop com.maker.guideline
adb -s 51dabb34 shell am start -a com.maker.guideline.SHORTCUT_CAPTURE -n com.maker.guideline/.MainActivity
adb -s 51dabb34 shell screencap -p /sdcard/p.png ; adb -s 51dabb34 pull /sdcard/p.png shot.png
```

结果：

| 检查项 | 结果 |
|---|---|
| 安装 | `Success`；`versionName=1.3.0` `versionCode=4` |
| **数据是否保住** | `firstInstallTime` 仍是 9-23（没被卸载重装）；截图里 **18 条老灵感、项目归属（含子项目「事件界面」）、逾期横幅**都在 |
| 启动 | 进程常驻，`topResumedActivity` 是 `.MainActivity` |
| 崩溃 / 缺插件 | logcat **无** `FATAL EXCEPTION`、**无** `MissingPluginException`、无 ANR |

**为什么截图能当"数据还在"的证据**：首页会把灵感逐条渲染出来，还带着项目名与创建时间。
跨两个版本升级后它们照常显示，说明"读旧文件 → 解析 → 重写"整条链路是通的 ——
这比 `run-as` 读文件更省事（见 §6.2，release 包读不了）。

**真机上自动验不到、必须本人点的**：清单的增删勾选、AI 设置与整理、系统分享面板。
原因就是上面那条 `INJECT_EVENTS` 限制，加 §6.3 的三条。

### 6.3 真机上**做不到**的事（别绕道浪费时间）

这两条都是 2026-09-25 实测确认的，别再试：

| 想做的事 | 结果 |
|---|---|
| 注入点击 / 滑动翻页去核对界面 | `SecurityException: Injecting input events requires … INJECT_EVENTS`。HyperOS 不给，**点击类验证只能由本人操作** |
| 用 `uiautomator dump` 读界面文字 | dump 出来的树里 41 个 `text=` **全是空值** —— Flutter 的语义树默认不向无障碍服务暴露。看不到任何文字，别指望它替你"读屏" |
| 让 release 包可调试以 `run-as` 读数据 | 在 `build.gradle.kts` 的 release 里加 `isDebuggable = true` 会让 Gradle 去要 **debug 版 Flutter embedding**，而这台机器连不上 `storage.googleapis.com`（见 §4 的镜像坑），构建直接失败 |

所以真机上**能自动验的只有**：装得上、启动不崩（logcat 无 `FATAL` / `MissingPluginException`）、
版本号对、截图看得到界面内容。**界面里的交互与系统分享面板必须本人点。**

升级后数据是否还在：截图就能看出来（老灵感、项目名、逾期条数都会渲染在首页），
不需要读文件 —— 这比 `run-as` 更省事，而且顺带验证了"解析 + 重写"整条链路。

### 6.4 版本号会被 `android/local.properties` 缓存（**踩过**）

`flutter build apk` 的版本号来自 `android/local.properties` 里的
`flutter.versionName` / `flutter.versionCode`，**不是实时读 `pubspec.yaml`**。
后果：改完 `pubspec.yaml` 的 `version:` 之后如果没跑过 `flutter pub get`，
构建出来的还是**上一个版本号**，而且全程不报错 ——
2026-09-25 就这样装上去一个 `1.2.0` 的包，`dumpsys` 才发现。

- 稳妥做法：构建时显式指定
  `flutter build apk --release --build-name=1.3.0 --build-number=4`；
- 或者构建前跑一次 `flutter pub get` 让它刷新；
- **`local.properties` 是 gitignore 的**，所以这纯粹是本机缓存问题，不入库、不影响别人。
- 验证办法：`aapt2 dump badging <apk>` 或装完 `adb shell dumpsys package com.maker.guideline`，
  认 `versionName` / `versionCode`。

## 7. 版本与发布

版本号规则见 `AGENTS.md` §6 与 `CHANGELOG.md` 开头（`主.次.修订`）。

**版本号与更新日志随功能改动走，不单独攒一轮**（当前口径：一个小版本对应一个提交）：

1. 改 `pubspec.yaml` 的 `version:`（形如 `1.5.5+29`），**同一个提交**里同步
   `lib/platform/data_directory.dart` 的 `AppInfo.version` / `buildNumber`，
   并**核对 README 顶上的「当前版本」**；
2. `CHANGELOG.md` 直接新增一节 `## [x.y.z] - YYYY-MM-DD`（**不再攒 `[Unreleased]`**），
   分类用固定词表 —— 见 `AGENTS.md` §8；
3. `flutter analyze` + `flutter test` 全绿，然后提交。

> 上面的四个落点（`pubspec.yaml`、`AppInfo`、README、`CHANGELOG.md`）漏一个就会红：
> `test/core/version_test.dart`（打包的 ↔ 界面显示的）与
> `test/core/docs_consistency_test.dart`（README、CHANGELOG ↔ pubspec）守着。
> 后者就是 2026-09-27 发现 README 滞后三个版本之后加的。

**发版是独立的一轮**（别和功能实现混在一起）：

4. `flutter build apk --release --build-name=<版本> --build-number=<构建号>`，把产物拷成
   `dist/guideline-<版本>.apk`。
   ⚠️ **构建时显式带上版本号**（或先跑一次 `flutter pub get`）：版本号会被
   `android/local.properties` 缓存，不然装上去的还是上一版的号，见 §6.4；
   ```powershell
   flutter build apk --release --build-name=1.5.5 --build-number=29
   ```
5. 打注释标签（标注标签里写清验收结果与安装包 sha256）：
   ```powershell
   git tag -a v1.5.5 -F .tools/tagmsg-155.txt
   git push origin main v1.5.5      # 推送只由仓库主人执行 —— 见 §8
   ```
   > **tag 现状**：`v1.5.2`~`v1.5.5` 四个版本**还没打标签**（只打到 `v1.5.1`）。
   > 补打时按各自的 `CHANGELOG.md` 那一节写标签说明，逐版补。
6. **发 GitHub Release 并挂上 APK**（2026-09-27 起有脚本，见 §7.1）：
   ```powershell
   $env:GH_TOKEN = '<你的令牌>'      # 只在当前会话；别写进任何文件
   .\tool\publish-releases2.ps1     # 幂等：已存在就同步正文、缺附件才上传
   ```
   正文与附件配置在脚本顶部，正文来源是 `tool/release-notes.md`（改那里再重跑即可）。

> **版本号只有一个源头**：界面取 `AppInfo.versionLabel`（由 `version` + `buildNumber` 拼出）。
> 1.0.0 时关于对话框与更多页各写了一份字面量，发版漏了一个 —— 不要再往界面里写版本字面量。
> 四个落点都在上面的第 1~2 步里，照做即可。

### 7.1 发布脚本（`tool/publish-releases2.ps1`）

2026-09-27 起，Release 的正文与 APK 附件由脚本调 GitHub API 完成，**幂等可重跑**：

| 输入 | 在哪 | 说明 |
|---|---|---|
| 令牌 | 环境变量 `GH_TOKEN` | 经典令牌要 `public_repo`，细粒度令牌要 **Contents: Read and write** |
| 正文 | `tool/release-notes.md` | 按 `## <版本>` 分节，脚本按 tag 取对应那一节 |
| 附件 | `dist/guideline-<版本>.apk` | 已存在同名附件就跳过，不重复上传 |

两个坑记在这里，免得下次再踩：

- `PATCH /releases/tags/<tag>` 在 **PowerShell 5.1** 的 `Invoke-RestMethod -Method Patch`
  下会返回 **404**（同一个 URL 的 GET 却正常）—— 改用 `PATCH /releases/<id>` 才通；
- 令牌只放环境变量、**不要落盘**；用完到 GitHub 设置里撤销（脚本不会保存它）。

## 8. 推送到 GitHub

> ⛔ **远端推送只由仓库主人执行。**
> 智能体 / 自动化**不要**执行 `git push`（任何分支、任何标签、任何大小），
> 也不要为了绕开它去改远端配置或换协议。
> 需要推送时：把提交留在本地，在汇报里附上本节命令并**请求授权**，等回复再动。
> 同一约定另写在 `AGENTS.md` §1（自动化会话的入口）与 `docs/开发节奏.md` §11。

公开仓库：<https://github.com/maker114/Guide-Line>（远端名 `origin`）。

```powershell
cd "E:\Guide Line"
git push -u origin main
git push origin --tags
```

远端可以用 SSH 或 HTTPS，两者指向同一个仓库：

| 方式 | 设置 | 前提 |
|---|---|---|
| SSH | `git remote set-url origin git@github.com:maker114/Guide-Line.git` | 本机公钥已加到 GitHub 账号 |
| HTTPS | `git remote set-url origin https://github.com/maker114/Guide-Line.git` | 凭据已存进 `credential.helper=store` |

本机网络到 `github.com:22` 被拒（`Connection refused`），所以 `~/.ssh/config` 里把
`github.com` 指向了 `ssh.github.com:443` —— **写法不用改**，`git@github.com:...` 照常用。
查看本机公钥：`Get-Content ~/.ssh/test.pub`；加到 <https://github.com/settings/ssh/new>。

推送前先确认没有把不该公开的东西带上去（`dist/` 与 `.tools/` 已在 `.gitignore` 里）：

```powershell
git status --short          # 应当没有未提交内容
git ls-files | Measure-Object -Line
```

## 9. 架构边界

`test/core/architecture_test.dart` 用源码扫描守住分层（ADR-024）：

| 层 | 允许依赖 | 禁止 |
|---|---|---|
| `lib/core` | 纯 Dart | import Flutter、依赖 features/ui/platform |
| `lib/features` | core | 依赖 ui、出现 `Platform.isX` |
| `lib/ui` | core / features / app / platform | —— |
| `lib/platform` | 插件与平台 API | —— |

**新增插件只能出现在 `lib/platform`**，业务层与界面层不得直接 import。
