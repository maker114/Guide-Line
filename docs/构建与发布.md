# 构建与发布

手机端（Android 单机版）的构建流程。命令都在**仓库根目录**执行。

## 1. 依赖环境

| 组件 | 版本（本机实测） | 说明 |
|---|---|---|
| Flutter | 3.47.5（Dart 3.13.4） | 装在 `E:\flutter` |
| Android SDK | Build-Tools 36 / Platform 35 / CMake 3.22.1 | 首次构建时由 Flutter 自动下载 |
| JDK | 随 Android Studio 安装 | Gradle 用 |

## 2. 日常命令

```powershell
flutter analyze --no-pub   # 静态检查，必须 0 问题
flutter test               # 全部测试，必须全绿
flutter build apk --release
```

产物：`build/app/outputs/flutter-apk/app-release.apk`（约 50 MB）。

> **在自动化 / 管道环境里跑 Flutter 命令时**，把输出重定向到文件再读，
> 否则 `flutter` 的进度输出可能把调用方卡住。

## 3. 启动图标

图标是**代码生成**的，不维护二进制素材：

```powershell
dart run tool/make_launcher_icons.dart
```

脚本按 4× 超采样自绘并手写 PNG 编码，输出五个密度的
`android/app/src/main/res/mipmap-*/ic_launcher.png`。
改图形只需要改脚本里的 `_onMark`（图案）与 `_gradientTop/_gradientBottom`（配色）。

## 4. 首次构建：Gradle 发行包可能下载卡住

`android/gradle/wrapper/gradle-wrapper.properties` 指向
`https://services.gradle.org/distributions/gradle-9.3.1-all.zip`（约 224 MB）。
本机实测 **Gradle 自带的下载器会卡在 0 字节**（同一时刻用浏览器/curl 拉同一 URL 却能跑满带宽）。

绕过办法：手动把发行包预置到 wrapper 期望的位置，Gradle 会自己校验并解压。

```powershell
$d = "$env:USERPROFILE\.gradle\wrapper\dists\gradle-9.3.1-all\9ot9r568e8zfvvd4mn8rbu1j0"
Remove-Item "$d\*.lck","$d\*.part" -Force -ErrorAction SilentlyContinue
curl.exe -L -o "$d\gradle-9.3.1-all.zip" `
  https://mirrors.cloud.tencent.com/gradle/gradle-9.3.1-all.zip
```

> `9ot9r568e8zfvvd4mn8rbu1j0` 是 Gradle 按 distributionUrl 算出来的目录名，
> 换 Gradle 版本时会变；先跑一次 `flutter build apk` 让它把目录建出来即可。
>
> 这只是**本机环境问题**，不是项目问题，所以仓库里的 `distributionUrl` 保持官方地址不动。

## 5. 另一个环境坑：Kotlin 增量编译缓存

本机（Windows + 仓库路径含空格）上，插件的 Kotlin 增量缓存会在 `compileReleaseKotlin`
结束时写不进去：

```
Execution failed for task ':android_file_picker:compileReleaseKotlin'.
> Could not close incremental caches … class-fq-name-to-source.tab, source-to-classes.tab
```

删掉 `build/` 也复现，属于环境问题。因此 `android/gradle.properties` 里关掉了增量编译：

```properties
kotlin.incremental=false
```

代价只是插件模块每次全量编译（本工程只有两个插件，影响很小）。**不要**为了提速把它改回 `true`。

## 6. 装到手机上

release 包用 Flutter 模板默认的 debug 签名，直接侧载即可：

```powershell
adb install -r build\app\outputs\flutter-apk\app-release.apk
```

或者把 APK 拷到手机上，在「设置 → 应用 → 安装未知应用」里允许文件管理器安装。

### 6.1 真机上怎么验证

**小米 15 Pro（HyperOS / Android 16）不允许 adb 注入输入事件**：

```powershell
adb -s 51dabb34 shell input swipe 540 1800 540 1200 300
# java.lang.SecurityException: Injecting input events requires ... INJECT_EVENTS permission
```

所以两条路分开走：

| 想验的东西 | 在哪验 | 怎么驱动 |
|---|---|---|
| 点击、滑动、输入法联动等**交互流程** | Android 15 模拟器（`emulator-5556`，`input tap/swipe` 可用） | adb 注入坐标 |
| **真机上的 IME 行为、启动路径、升级后数据是否还在** | 小米 15 Pro | 应用自己的 Intent + 截图 |

真机上能做的三件事：

```powershell
# 1) 冷启动速记路径（长按图标速记走的是同一个 action）
adb -s 51dabb34 shell am force-stop com.maker.guideline
adb -s 51dabb34 shell am start -a com.maker.guideline.SHORTCUT_CAPTURE -n com.maker.guideline/.MainActivity

# 2) 键盘到底弹没弹（**不要只看截图**，这里踩过一次：截图看着像弹了）
adb -s 51dabb34 shell dumpsys input_method | Select-String mInputShown

# 3) 看界面 / 确认版本与数据还在
adb -s 51dabb34 shell screencap -p /sdcard/p.png
adb -s 51dabb34 pull /sdcard/p.png shot.png
adb -s 51dabb34 shell dumpsys package com.maker.guideline | Select-String versionName
```

> `screencap` 的输出**必须**走「手机存文件 → `adb pull`」。
> 在 PowerShell 里 `adb exec-out screencap -p > x.png` 会被按文本重写换行，得到的 PNG 是坏的。

## 7. 版本与发布

版本号规则见 `CHANGELOG.md` 开头（`主.次.修订`）与设计文档 §10：

1. 改 `pubspec.yaml` 的 `version:`（形如 `1.1.0+2`）；
2. 把 `CHANGELOG.md` 的 `[Unreleased]` 收成 `[1.1.0] - YYYY-MM-DD`，并给下一个版本留回空的 `[Unreleased]`；
3. `flutter analyze` + `flutter test` 全绿；
4. `flutter build apk --release`，把产物拷成 `dist/guideline-<版本>.apk`；
5. `git tag -a v1.1.0 -F .tools/tagmsg.txt`（标注标签里写清验收结果与安装包 sha256）。

> **版本号只有一个源头**：界面取 `AppInfo.versionLabel`（由 `version` + `buildNumber` 拼出）。
> 1.0.0 时关于对话框与更多页各写了一份字面量，发版漏了一个 —— 不要再往界面里写版本字面量。

## 8. 推送到 GitHub

> ⛔ **远端推送只由仓库主人执行。**
> 智能体 / 自动化**不要**执行 `git push`（任何分支、任何标签、任何大小），
> 也不要为了绕开它去改远端配置或换协议。
> 需要推送时：把提交留在本地，在汇报里附上本节命令并**请求授权**，等回复再动。
> 同一约定另写在 `AGENTS.md` §1（自动化会话的入口）与 `docs/开发节奏.md` §11。

公开仓库：<https://github.com/maker114/Guide-Line>（远端名 `origin`）。

```powershell
cd "E:\Guide Line"
git push -u origin main
git push origin --tags
```

远端可以用 SSH 或 HTTPS，两者指向同一个仓库：

| 方式 | 设置 | 前提 |
|---|---|---|
| SSH | `git remote set-url origin git@github.com:maker114/Guide-Line.git` | 本机公钥已加到 GitHub 账号 |
| HTTPS | `git remote set-url origin https://github.com/maker114/Guide-Line.git` | 凭据已存进 `credential.helper=store` |

本机网络到 `github.com:22` 被拒（`Connection refused`），所以 `~/.ssh/config` 里把
`github.com` 指向了 `ssh.github.com:443` —— **写法不用改**，`git@github.com:...` 照常用。
查看本机公钥：`Get-Content ~/.ssh/test.pub`；加到 <https://github.com/settings/ssh/new>。

推送前先确认没有把不该公开的东西带上去（`dist/` 与 `.tools/` 已在 `.gitignore` 里）：

```powershell
git status --short          # 应当没有未提交内容
git ls-files | Measure-Object -Line
```

## 9. 架构边界

`test/core/architecture_test.dart` 用源码扫描守住分层（ADR-024）：

| 层 | 允许依赖 | 禁止 |
|---|---|---|
| `lib/core` | 纯 Dart | import Flutter、依赖 features/ui/platform |
| `lib/features` | core | 依赖 ui、出现 `Platform.isX` |
| `lib/ui` | core / features / app / platform | —— |
| `lib/platform` | 插件与平台 API | —— |

**新增插件只能出现在 `lib/platform`**，业务层与界面层不得直接 import。
