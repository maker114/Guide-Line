# 工程说明

> **这份是给要改代码的人看的**：分层、数据怎么存、依赖、怎么跑测试与构建。
> 想了解这个软件**能做什么**，看 [`README.md`](../README.md)；
> 想知道**为什么这么做**，看 [`决策索引.md`](决策索引.md)。

## 1. 分层

```
lib/
  core/       数据层与规则 —— 纯 Dart，**禁止 import Flutter**
  features/   业务逻辑，Workspace 装全部业务规则
  app/        应用装配与动作门面
  ui/         界面，两套外壳（手机底部四格 / 电脑侧栏）加各 Tab 与页面
  platform/   平台适配 —— **唯一允许出现平台判断与插件的地方**
docs/         契约、口径、计划与工程说明
test/         契约回归、规则、存储、架构边界、界面与外壳
tool/         一次性脚本（图标生成、演示数据生成与自检、发布上传、构建恢复）
```

两条边界**各有各的守卫**（别记混）：

| 规矩 | 谁守 | 它看什么 |
|---|---|---|
| `lib/core` 不许 import Flutter、层间依赖方向不许反、不许出现云端 SDK | `test/core/architecture_test.dart` | 扫描源码；**从不看第三方 package** |
| **新增插件只能出现在 `lib/platform`** | `test/core/platform_boundary_test.dart` | `lib/platform` 之外任何文件 import 第三方包就红；另有一份"当前在用哪些插件、各几处"的登记册 |

`platform_boundary_test.dart` 的登记册是有意写死的：**依赖面貌变了必须由一个提交显式说明**，
而不是悄悄发生。

## 2. 数据与安全

- **单文件存储** `guideline.json`：临时文件 → flush → rename 的**原子替换**。
  跨实体操作天然全有或全无 —— 比如合并灵感会同时改项目与灵感，不会只成一半。
- **界面偏好单独一个** `ui_prefs.json`：折叠状态、主题、提醒设置这类改动频繁，
  不值得为它重写整份数据；它**不进备份、不进导出**（丢了只是回默认值）。
- **备份轮转**：滚动备份最近 **10 份**（`guideline.backup.N.json`）；
  每天第一份保存留日快照、最近 **7 天**（`guideline.daily.YYYYMMDD.json`）。
  滚动备份可以**单独删除**，但**至少保留一份**。
- **备份的时机**：写数据是"改一下就存住"（防断电、防杀进程）；轮转发生在
  **一段编辑会话的第一笔写入之前**，留的是"进这个页面之前"那一版 ——
  同一段会话里再改多少笔都不再留，否则改得越勤、老备份被挤掉得越快。
  不在编辑会话里的散点保存按 **5 分钟**最小间隔节流。
- **损坏永不静默**：主文件读不出来就隔离现场，并自动从最近备份恢复，
  同时告诉你恢复用了哪一份、隔离文件在哪。
- **导出 / 导入**：整份数据导出为 `.json.gz` 经系统分享发出；导入前给摘要与二次确认，
  替换前自动留一份备份，导错了能退回。电脑端旧格式（v1 四文档信封）也能直接导入。
- **`apiKey` 与 GitHub Token 只在系统安全存储**（Android Keystore），
  **不进备份、不进导出**；提示词与模型返回的原文也不落盘。

字段、取值与序列化规则的**权威**是 [`spec/数据契约.md`](spec/数据契约.md)。

## 3. 依赖

Flutter 稳定版（开发时用的是 3.47.5）、Dart SDK `^3.13.4`。

**`pubspec.yaml` 里声明了八个，真在用的是七个**：

| 包 | 干什么 |
|---|---|
| `path_provider` | 找应用私有目录 |
| `share_plus` | 导出时调系统分享 |
| `file_picker` | 导入 / 选背景图时挑文件 |
| `http` | AI 整理、GitHub 备份同步 |
| `flutter_secure_storage` | `apiKey` 与 GitHub Token |
| `flutter_local_notifications` | 到点提醒（本地调度） |
| `timezone` | 给上面那个提供内置的 `tz.UTC`（**不读时区数据库**） |

第八个是 Flutter 模板自带的 `cupertino_icons`，本工程一处都没 import（2026-10-01 核实）——
所以"真在用七个"说的是"代码里真的 import 了谁"，不是"声明了几个"。

前五个各有 Windows 实现，电脑端不为它们额外引依赖；**提醒那两个不一样**：
`flutter_local_notifications` 会把 `flutter_local_notifications_windows` 带进电脑端的构建
（构建产物里能看到那个 dll），但**电脑端一处都不调用它** —— 提醒只在手机端做（ADR-097）。

> 提醒这两个**刻意写死精确版本**（其余都是 `^`）：插件的 buildscript 自己钉着
> Android Gradle Plugin 的版本，放开会让一次 `pub get` 就换掉整条原生依赖链。

## 4. 开发与验收

```powershell
flutter analyze --no-pub    # 必须 0 问题（约 6 秒）
flutter test --no-pub       # 必须全绿（当前约 1003 例，约 34 秒）
flutter build apk --release     # 手机端产物 build/app/outputs/flutter-apk/app-release.apk
flutter build windows --release # 电脑端产物 build/windows/x64/runner/Release/guideline.exe
```

- **跑测试很快**：全量约 1003 例约 **34 秒**，`analyze` 约 **6 秒** ——
  所以"少跑点测试"省不下什么，别往那个方向优化。
  （精确条数以 `flutter test` 输出的 `+N` 为准：静态数出来的声明条数与它不是同一个数，
  循环里会生成用例。这条口径由 `test/core/docs_consistency_test.dart` 守着：
  它只要求**不小于**静态声明条数，不钉精确相等。）
- **构建时显式给版本号**：`android/local.properties` 会缓存
  `flutter.versionName` / `flutter.versionCode`，不显式指定就会打出一个
  与界面显示不一致的包，而且全程不报错。
- **演示数据**（写文档、拍截图时用，不含任何真实内容）：
  `dart run tool/demo_seed.dart` 生成，`dart run tool/demo_verify.dart` 自检。
  生成的文件在 `dist/guideline-演示数据.json`（+ 等价的 `.json.gz`）。
- **怎么选验证手段、怎么排一轮的节奏**：见 [`开发节奏.md`](开发节奏.md)。
- **环境坑**（Gradle 镜像、`kotlin.incremental=false`、AVD 位置、HyperOS 侧载与
  adb 注入限制、版本号缓存）：见 [`构建与发布.md`](构建与发布.md)。
