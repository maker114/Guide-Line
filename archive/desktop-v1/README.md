## 2. 为什么归档

1. **云端后端始终未定**：LeanCloud 已停服 → CloudBase 需套餐 → 阿里云 / 对象存储 / Git 私有仓库都在对比，
   而**双端同步**在任何方案下都需要一个云端或一台常开设备；
2. **重新审视需求**：这是**单人自用**的生活管理工具，主要使用场景在**手机**上（随手速记），
   电脑端「深度编辑」的价值不足以支撑整套双端架构的复杂度；
3. 因此决定：**先做纯手机单机应用**，把「同步」降级为将来的可选增强
   （数据模型与导出格式已为此留了口子）。

## 3. 对手机端仍然有效 / 可复用的部分

| 资产 | 复用建议 |
|---|---|
| `lib/core/models/*`（4 实体 + 墓碑 + 枚举） | ✅ **直接复用**：纯 Dart，无 Flutter、无平台依赖 |
| `lib/core/json/canonical.dart` + 契约样本测试 | ✅ 直接复用：保证 JSON 稳定可读、可跨版本演进 |
| `lib/core/rules/*`（完成判定 / 级联 / 归档区 / 层级移动） | ✅ 直接复用：全部业务规则都在这里 |
| `lib/core/store/*`（原子写 / 崩溃隔离 / 本地文件集） | ✅ 直接复用（手机端只需换成应用私有目录） |
| `lib/features/workspace.dart`（业务层） | ✅ 复用为主；可**去掉同步相关部分**（`pending_tx` / `version` / `markSynced`） |
| `lib/features/portability.dart`（导出 / 导入） | ✅ **单机下更重要**：没有云端备份时，这是唯一的数据安全出口 |
| 数据契约（根 `docs/spec/数据契约.md`） | ✅ 仍然权威 |
| `docs/双端软件架构设计.md` 的 §3 / §4（产品定义与数据模型） | ✅ 仍然有效；§1 / §2 / §5 / §6 / §7（云端、同步、双端互联）作废 |
| UI 规则（4.8 上下分区合并、4.9 任务树呈现、4.10 归档区） | ✅ 交互规则照搬，只把外壳换成手机端 |
| Android 系统级入口调研（原 §8.2：小组件 + 通知栏；`RemoteViews` 不支持 `EditText`） | ✅ **单机下重新变得关键**（速记入口） |

## 4. 明确不要带过去的部分

- ❌ 同步引擎 / `SyncBackend` / 云函数 / 后端选型对比 → 全部**随同步需求一起搁置**
- ❌ 账号体系、配对码、恢复码、自定义登录票（单机不需要身份）
- ❌ Windows 外壳、托盘、开机自启、全局快捷键
- ❌ 双端契约测试的前提（「两端逐字节一致」）—— 单端只需保证**自己的旧版本能读新写的数据**

## 6. 若要重新启用本目录

它是完整可构建的工程，直接在本目录内执行即可：

```bash
cd archive/desktop-v1
flutter pub get
flutter run -d windows
```

> 注意：根目录将来的 `analysis_options.yaml` 应把 `archive/**` 加入 `analyzer.exclude`，
> 避免用手机端工程的依赖去分析这份归档代码。
